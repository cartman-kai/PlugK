# 数据表与资源

## 资源位置

模板数据位于：

```text
game_file/mb/assets
```

其中 `assets` 是解包工具添加出的目录。

视频资源位于游戏目录的 `dhp/`。1.05 非 Steam 版已动态确认 `dhp/begin.dhp` 是开场动画文件，可由 VLC 直接播放；游戏内通过 DirectShow 路径播放，不是 `game_file/mb/assets` 表格资源。

## 文本格式

- 编码：GB2312/GBK。
- 分隔：tab。
- 来源：早期 Excel 导出的 txt 文本。

## Font.txt

2.01 解包资源位于 `game_file/201_fol/mb/assets/Font.txt`。当前包含 `ToolTip`、`敌人人名`、`big`、`对话` 四条记录，默认字体均为宋体，字号字段分别为 `9/9/18/9`。

表头为 `Name / nHeight / fnWeight / lpszFace`，但 2.01 `sub_4C7640` 的静态分析确认 `fnWeight` 实际用于缩放 `LOGFONTA.lfWidth`，并不写入 `lfWeight`。开发字体替换功能时应保留原记录生成的高度和宽度参数，只替换字体名称，不应按表头误改字重。

读取和统计数据表时应注意编码，避免用 UTF-8 默认解析导致中文字段或名称损坏。

## 技能与手势相关表

技能、招式和必杀技至少涉及以下表：

| 表 | 路径 | 用途 |
| --- | --- | --- |
| `MethodPoint.txt` | `assets/MethodPoint.txt` | 手势数据表。手势识别成功后得到对应招式 ID，再写入准备释放字段 |
| `Init.txt` | `assets/player/Init.txt` | 角色模板，包含角色 ID、初始技能/招式等配置 |
| `skill.txt` | `assets/player/skill.txt` | 技能模板，包含技能 ID、招式 ID、系号、组号、等级和消耗 |

注意：运行时释放技能/必杀技使用的是招式 ID，也就是 `method_id`。角色是否拥有某个技能，应通过角色技能链中的技能 ID 判断。

已确认手势示例：

| 手势形状 | `MethodPoint` ID |
| --- | ---: |
| `M` | 11 |
| `W` | 10 |
| `|_|` | 13 |

## PropMdl

`PropMdl.txt` 是当前随机掉落分析中已确认会参与查询的物品模板表。

已知查询字段：

| 字段 | 含义 |
| --- | --- |
| 8 | 等级/品级 |
| 2 | 物品类型 |

当前 `game_file/mb/assets/PropMdl.txt` 中，随机掉落相关基础类型记录统计：

| 类型 | 含义 | 记录数 |
| ---: | --- | ---: |
| 10 | 药品 | 14 |
| 20 | 可投掷物品 | 19 |
| 30 | 可镶嵌的宝石 | 39 |
| 35 | 疑似高难度宝石 | 0 |

结论：在这份 1.05 资源表下，Type 35 不会作为 `PropMdl` 查询结果自然掉落。如果其他逻辑显式要求 Type 35，则仍可能走 Type 35 自己的物品表查询路径；这需要按调用方单独确认。

## 运行时表头

1.05 动态调试确认：

- `0x00548340` 是 `PropMdl` 表头，运行时形态为 `[count, base]`。
- 当前调试进程中 `dword(0x00548340) = 0x9A`。
- `0x00548344` 不是独立表头，而是表头中的 base 指针槽；当前调试进程中 `dword(0x00548344) = 0x0CFF214C`。

2.01 动态调试确认：

- `0x005788D0` 的 `PropMdl` 表头运行时形态为 `[count, base]`。
- 当前调试进程中 count 为 `0xCF`。

## 运行时记录结构

`PropMdl` 运行时记录数组中，每条记录 16 字节，当前确认结构：

| 偏移 | 含义 |
| ---: | --- |
| `+0x00` | 记录索引或内部序号 |
| `+0x04` | 整数字段数量 |
| `+0x08` | 整数字段数组指针，每个字段 4 字节 |
| `+0x0C` | 文本/指针数组指针 |

整数字段数组中已确认字段：

| 字段 | 含义 |
| ---: | --- |
| 1 | 物品 ID |
| 2 | 物品类型 |
| 8 | 等级/品级，随机掉落查询使用 |

文本/指针数组中，`ptrs[0]` 指向物品显示名称，字符串编码为 GBK。

1.05 调试样例：

```text
0x00548340: count = 0x9A
0x00548344: base  = 0x0CFF214C

record[0] at 0x0CFF214C:
  +0x00 = 0
  +0x04 = 0x10
  +0x08 = 0x025739C0
  +0x0C = 0x02573974

dword(0x02573974) = 0x0D8D5068
0x0D8D5068 = "金钱" (GBK)
```

注意：曾观察到整数字段数组中较靠后的字段会保存指向其他记录的地址，不能直接等同于名称指针。读取物品名时，优先使用 `record + 0x0C -> ptrs[0]` 这条路径。

## RandProp

`RandProp.txt` 是敌人随机掉落配置表。1.05 静态分析确认，战斗随机掉落主函数 `sub_452420` 会按敌人 ID 在该表中查一行配置。

表头字段：

| 字段 | 运行时字段号 | 含义 |
| --- | ---: | --- |
| 角色名称 | 0 | 显示名称 |
| 角色ID | 1 | 敌人/角色 ID，`sub_452420` 的第一个参数会用它查询本表 |
| 掉宝机率 % | 2 | 是否进入物品掉落判定 |
| 掉宝数量min | 3 | 物品掉落数量下限 |
| 掉宝数量max | 4 | 物品掉落数量上限，当前代码按 `min + rand() % (max - min)` 取值，表现为不包含 max |
| 掉钱机率 % | 5 | 是否生成金钱掉落 |
| 掉钱数量min | 6 | 金钱数量下限 |
| 掉钱数量max | 7 | 金钱数量上限，当前代码按 `min + rand() % (max - min)` 取值，表现为不包含 max |
| 1..9 | 8..16 | 物品品质/掉落档位权重，命中后返回 `1..9` 作为 `PropMdl` 的等级/品级查询条件 |
| 固定販賣物品 ID | 17 | 商店/贩卖相关字段；不属于 `sub_452420` 的战斗随机掉落主流程 |
| 固定販賣物品數量 | 18 | 商店/贩卖相关字段 |
| 亂數販賣物品 ID 範圍 | 19 | 商店/贩卖相关字段 |
| 亂數販賣物品總量 | 20 | 商店/贩卖相关字段 |

注意事项：

- 金钱和物品是两个独立判定。金钱命中后不会阻止后续物品判定。
- `1..9` 列只决定物品品质/掉落档位，不决定物品类型。物品类型在 `sub_452200(level, -1)` 中按难度随机决定。
- 普通击败时，品质抽取使用 `rand() % 90`，因此权重累计区间的 `90..99` 在普通掉落中不可达；连招 bonus 会把这个 roll 往高处推并封顶到 99。
