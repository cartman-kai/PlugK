# 角色运行时内存

## 角色对象入口

角色主要信息通过一个全局地址保存指针，指向角色对象。

| 版本 | 全局地址 | 说明 |
| --- | --- | --- |
| 1.05 | `0x00558AC4` | 保存角色对象指针 |
| 2.01 | `0x00589A44` | 保存角色对象指针 |

2.01 动态调试确认 `[0x00589A44]` 指向角色对象。

## 1.05 / 2.01 角色数据对象

1.05 的 `sub_4890A0` 在没有现成角色对象时分配 `0x378` 字节，调用 `sub_47D3E0` 构造并写入 `dword_558AC4`。`sub_455160` 的存档读取临时对象也分配相同大小，能够交叉确认对象尺寸。因此本节中的偏移只适用于角色数据对象，不适用于受击结算使用的战斗角色对象。

2.01 的 `sub_4985C0` 同样分配 `0x378` 字节，调用 `sub_48C140` 构造并写入 `dword_589A44`。随后 `sub_48D650` 依次调用 `sub_48D690` 绑定 Init 模板、调用 `sub_48D350` 初始化属性与初始物品/技能。对象尺寸、基础属性、模板指针和六个倍率偏移均与 1.05 相同。

角色模板绑定链路：

```text
sub_4890A0
    分配 0x378 字节
    sub_47D3E0：构造角色数据对象
    写入 dword_558AC4
    sub_47E8B0(this, role_id)：新角色初始化包装
        sub_47E8F0(this, role_id)：按 ID 绑定 Init 模板
        sub_47E5A0(this)：新角色属性和初始物品/技能
```

| 偏移 | 含义 | 来源 |
| ---: | --- | --- |
| `+0x20` | 金钱，来自 `Init` 字段 29 | IDA 静态分析 |
| `+0x38` | 基础 AT | IDA 静态分析 |
| `+0x3C` | 基础 DF | IDA 静态分析 |
| `+0x40` | 基础最大 HP | IDA 静态分析 |
| `+0x44` | 基础最大 MP/气 | IDA 静态分析 |
| `+0x48` | 基础 Stamina | IDA 静态分析 |
| `+0x4C` | 基础锋利值 | IDA 静态分析 |
| `+0x50` | 怒气上限/容量；初始化为 0，`sub_480D70` 增加并封顶到 9999 | IDA 静态分析 |
| `+0x54` | 基础命中率 | IDA 静态分析 |
| `+0x58` | 怒气提升力，来自 `Init` 字段 24 | IDA 静态分析 |
| `+0x5C` | 回血率；难度 1/2/3 初始化时再除以 2/3/4 | IDA 静态分析、数据表验证 |
| `+0x60` | 回气率 | IDA 静态分析 |

## 1.05 / 2.01 属性倍率

1.05 `sub_47E8F0` 与 2.01 `sub_48D690` 都把以下 6 个 `float` 初始化为 `1.0`。属性 getter 会把基础值与对应倍率组合：

| 索引 | 偏移 | 作用属性 |
| ---: | ---: | --- |
| 0 | `+0x2C8` | 移动速度 |
| 1 | `+0x2CC` | 回气率 |
| 2 | `+0x2D0` | 回血率 |
| 3 | `+0x2D4` | DF |
| 4 | `+0x2D8` | AT |
| 5 | `+0x2DC` | 最大 HP |

这些字段很适合作为状态技能、受击和装备效果的动态观察点。它们不是连续受击减伤的计数器；已确认的隐藏伤害除数位于另一个战斗角色对象中。

## 1.05 战斗角色对象

`sub_4236B0` 的 `this` 是战斗角色对象，其偏移已超过角色数据对象的 `0x378` 大小。当前与受击相关的候选布局：

玩家战斗对象可通过当前游戏上下文取得：

```text
dword_5585C4
    -> +0x30 玩家引用对象
    -> +0x0C 角色句柄
    -> sub_420D50(handle)
    -> 玩家战斗对象
```

玩家构造函数 `sub_42FB30` 会把对象 vtable 设置为 `off_528CD4`，并把对象 `+0x18` 的玩家数据索引设为 `1`。`sub_42FDB0` 使用该索引经 `sub_4892B0` 反查玩家数据对象。plugK 战斗调研模块同时检查 `off_528CD4`，避免把其它场景对象误认为玩家。

| 偏移 | 含义 | 来源 |
| ---: | --- | --- |
| `+0x1A7` | 战斗阵营/分组；`sub_421F40` 和内置 `SetGroup` 路径维护，与来源相等时伤害先减半；玩家复制敌人分组后敌人停止攻击 | IDA 静态分析、2026-07-30 动态验证 |
| `+0x1AF + effect_id` | 战斗效果启用标记字节；`effect_id=44` 时伤害再减半 | IDA 静态分析、数据表及 2026-07-30 动态验证 |
| `+0x3A2` | 当前 HP，`float`；`sub_424770` 增减并夹紧到最大 HP | IDA 静态分析 |
| `+0x3A6` | 当前 MP/气，`float`；`sub_424E90` 以最大 MP 计算百分比 | IDA 静态分析 |
| `+0x3AA` | 当前 Stamina，`float`；`sub_424DE0` 以最大 Stamina 计算百分比 | IDA 静态分析 |
| `+0x3B6` | 当前怒气；`sub_424EC0` 增减并夹紧到角色数据对象 `+0x50` 的上限 | IDA 静态分析 |
| `+0x412` | 本轮不同攻击招式/动作 ID 数量 | IDA 静态分析 |
| `+0x416` / `+0x41A` | 招式/动作 ID 链表头/尾 | IDA 静态分析 |
| `+0x422` | 本轮不同攻击来源键数量；大于 1 时作为伤害除数；进入状态 110“受伤旋飞”时会整体清零 | IDA 静态分析、1.05 有限捕获动态验证 |
| `+0x426` / `+0x42A` | 攻击来源键链表头/尾 | IDA 静态分析 |
| `+0x432` | 短期受击事件计数，按 `float` 累加；可独立归零，进入状态 110“受伤旋飞”时会和来源集合一起归零 | IDA 静态分析、1.05 有限捕获动态验证 |

完整结算、清空边界和动态验证方案见[受击、命中与连续受击保护](../systems/combat_damage.md)。

## 2.01 战斗角色对象静态映射

2.01 玩家战斗对象构造函数为 `sub_439040`，虚表为 `off_551E2C`。对象 `+0x18` 仍保存玩家数据索引 `1`，`sub_4392C0` 通过该索引反查角色数据对象；虚表 `+0x90` 的 `sub_439330` 固定读取关联 Init 记录字段 6（DF4）。这与 1.05 玩家战斗对象链完全同构。

战斗对象前部的分组和效果数组未移动，后半段字段相对 1.05 后移 `0x0C`：

| 2.01 偏移 | 含义 | 1.05 偏移 |
| ---: | --- | ---: |
| `+0x1A7` | 战斗阵营/分组 | `+0x1A7` |
| `+0x1AF + effect_id` | 战斗效果启用标记字节 | 相同 |
| `+0x3AE` | 当前 HP，`float` | `+0x3A2` |
| `+0x41E` | 不同攻击招式/动作 ID 数量 | `+0x412` |
| `+0x422` / `+0x426` | 招式/动作 ID 链表头/尾 | `+0x416` / `+0x41A` |
| `+0x42E` | 不同攻击来源键数量；大于 1 时作为伤害除数 | `+0x422` |
| `+0x432` / `+0x436` | 攻击来源键链表头/尾 | `+0x426` / `+0x42A` |
| `+0x43E` | 短期受击事件计数，按 `float` 累加 | `+0x432` |
| `+0x41A` | 来源保护周期工作字段；无来源正常初始值为 `0`，周期衰减路径每次处理绝对值 `0.02` | 2.01 IDA 静态分析、面板及 2026-08-02 Hook 动态验证 |

2.01 的玩家战斗对象获取链、vtable `0x00551E2C`、当前 HP、来源数 `+0x42E`、受击计数 `+0x43E` 和自然清空边界已由 Combat Probe 动态校验。切图、读档、复活后的对象生命周期仍属于其它调研主题，不影响本表的连续受击保护结论。

## 容器槽位值

- 空位：`-1`。
- 非空：物品池索引。

## 技能链表

1.05 与 2.01 角色对象中的技能链表偏移已共用验证。

| 偏移 | 含义 |
| ---: | --- |
| `+0x364` | 技能链表头节点指针 |

技能链节点当前确认字段：

| 节点偏移 | 含义 |
| ---: | --- |
| `+0x00` | next 指针 |
| `+0x08` | 技能 ID |

已知用途：

- 一键洗技能功能通过该链表枚举当前角色已学习技能。
- 必杀技快捷释放通过该链表确认角色是否拥有对应必杀技技能 ID。
- 释放技能或必杀技时，游戏函数使用的是招式 ID；技能链中保存的是技能 ID，两者不要混用。
