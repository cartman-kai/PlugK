# 敌人 HUD 与血条显示

## 原版绘制链

1.05 与 2.01 的敌人顶部信息绘制是同构的：敌人头像、选中框、血条和名称都由一个敌人绘制函数完成。该函数的入口虽然被 IDA 标为 `__stdcall`，实际入口使用 `ECX` 保存绘制上下文，并从栈上取 4 个参数；plugK 的 detour 必须使用 `__fastcall(pThis, _edx, surface, role_id, x, y)` 形式，不能改成普通 `__stdcall`。

| 项目 | 1.05 | 2.01 |
| --- | --- | --- |
| 敌人绘制函数 | `sub_4B0A60` / `0x004B0A60` | `sub_4C3C50` / `0x004C3C50` |
| 名称文字调用返回边界 | `0x004B0BF1` | `0x004C3DE1` |
| 敌人对象解析 | `sub_420D50` / `0x00420D50` | `sub_429340` / `0x00429340` |
| 血量分段 | `sub_424AF0` / `0x00424AF0` | `sub_42D7A0` / `0x0042D7A0` |
| 名称记录读取 | `sub_4D00B0` / `0x004D00B0` | `sub_4E4D90` / `0x004E4D90` |

敌人对象的投影虚函数位于虚表 `+0x1C`。调用后，地面投影坐标写入对象 `+0x48/+0x4C`，角色模型及其部件合并后的屏幕包围盒写入 `+0x34/+0x38/+0x3C/+0x40`（左、上、宽、高）。因此底部血条仍使用 `+0x48/+0x4C` 的地面坐标，而名称应使用包围盒的上边界 `+0x38`，不能再用固定的 `screen_y - 24`。

## 底部血条实现

配置项 `UI.MoveEnemyHpToBottom` 对应 `g_pk_config.move_enemy_hp_bottom`，默认关闭。开启时仍只 Hook 敌人绘制函数，但 detour 不再调用原函数，而是：

1. 通过原版敌人对象解析函数取得对象并刷新投影坐标。
2. 调用原版血量分段函数取得段内百分比和分段编号。
3. 对血条资源容器按原版分段编号取“已填充”和“空”精灵（slot `segments + 1` / slot `segments`），保留原版的颜色和段内比例逻辑；底部显示仍使用当前的相对窄宽度，但最终绘制高度缩为原精灵高度的一半。
4. `ShowEnemyHp` 开启时，通过共享文字函数的原始 trampoline 将 `HP: current/max` 绘制在底部血条下方；关闭时只保留常驻血条。

血条资源与头像资源使用不同的绘制上下文字段。两版原版血条路径直接把 `*(pThis + 0x118) + 32 * *(pThis + 0x110)` 作为血条资源容器，其中 `+0x118` 是容器基址、`+0x110` 是组索引；随后仅调用资源表项查找函数按分段编号取精灵，再调用资源解析函数。不能把头像路径中的“敌人记录字段 3 → 资源组”链复用到血条上。裁剪参数仍使用 `+0x58/+0x5C`，资源记录宽高位于精灵对象 `+0x0C/+0x10`。

底部模式不调用原版敌人绘制函数，因此不会绘制头像、顶部血条或顶部选中框，也不会触发共享文字 detour 的顶部 HP 追加。原版血条函数 `sub_4B1FF0` / `sub_4C5340` 还被其它 UI 路径使用，不能全局 Hook；实现直接调用精灵虚表，避免影响其它路径。

## 名称显示与悬停/锁定目标

底部模式下，名称不再绘制在血条内部。1.05 的 `sub_4B25A0` 和 2.01 的 `sub_4C58F0` 直接把传入的 `y` 作为 `TextOutA` 左上角坐标，原版名称到下一文字行的步长约为 14 像素；因此名称使用敌人投影后包围盒顶部上方的一行文字：`bounds_top - 14 - 2`（另留 2 像素间距），横坐标使用包围盒中心；如果包围盒读取失败才回退到旧的 `screen_y - 24`。只有当前对象等于游戏已经计算出的鼠标目标或锁定目标时才绘制名称，其它敌人只显示常驻血条。

`Role.txt` 的部件字段中存在 `HD`/`HDS` 项，`game_file/105/fol/slr/SprRole.h` 和 2.01 对应资源头也存在同名资源；这可以确认 `HD` 是头部相关部件。但投影函数会把基础模型和附加部件的实际屏幕包围盒统一合并，直接使用这个包围盒顶部比单独解析 HD 资源坐标更适合不同角色、动作和装备。

- 1.05：鼠标管理器指针位于全局 `0x00557D1C`，目标字段为 `+0x3C`；锁定目标使用 `sub_42B280(sub_477790(*(dword_5585C4 + 0x30)))`。
- 2.01：鼠标管理器指针位于全局 `0x00588BA8`，目标字段为 `+0x3C`；锁定目标使用 `sub_434350(sub_4861A0(*(dword_589544 + 0x30)))`。

这些解析函数均为游戏原生 `thiscall`，C 侧统一以 `__fastcall(pThis, _edx, ...)` 调用；读取全局对象和目标字段前先做可读性检查，不自行实现鼠标坐标碰撞。

## Hook 边界与验证状态

- `ShowEnemyHp=0` 且 `MoveEnemyHpToBottom=0` 时，不创建敌人绘制 Hook。
- `MoveEnemyHpToBottom=1` 时创建敌人绘制 Hook；无论 `ShowEnemyHp` 是否开启，都会显示底部常驻血条，名称只在悬停或锁定时显示，数字行仍由 `ShowEnemyHp` 控制。
- `sub_4B25A0` / `sub_4C58F0` 的共享文字 Hook 仍归 `item.c` 管理；底部模式复用其原始 trampoline，不重复创建文字 Hook。
- 已完成 IDA 静态分析；资源链曾因误用头像索引链导致 `sub_4EEA20` 崩溃，已按原版血条调用序列修正。包围盒顶部坐标、缩半后的血条高度、不同分辨率下的裁剪和死亡状态仍需进入两版游戏手工验证。
