# 掉落机制

## 基本流程

击败敌人时，游戏会根据敌人可掉落范围随机决定掉落内容。

掉落机制至少包含以下路径：

- 金钱/物品分支。
- 按权重抽取等级或品级。
- 根据等级、类型、难度选择具体物品 ID。
- 创建并投放地面物品。
- 敌人背包已有物品吐出。
- 连招得分触发的二次掉落。

实现掉落相关 hook 时，需要区分随机掉落和其他共享选物路径，避免影响商店、脚本、任务或敌人已有物品吐出。

## RandProp 驱动的主流程

1.05 静态分析确认，普通击败敌人时会进入 `sub_424180(this, 0, 0.0)`，再调用 `sub_452420(rand_prop_id, position, bonus)`。其中 `rand_prop_id` 来自敌人数据，`sub_452420` 用它查询 `RandProp.txt`。2.01 对应的主流程函数是 `sub_45E5A0`，查询运行时 `RandProp` 表 `0x00578D18`。

`sub_452420` 中的顺序是：

1. 读取 `RandProp` 行。
2. 先判定金钱掉落。
3. 再判定物品掉落。
4. 如果物品掉落命中，按 `掉宝数量min/max` 得到本次尝试掉落的物品数量。
5. 每个物品各自调用 `sub_452390` 抽一次 `1..9` 品质/掉落档位。
6. 每个品质档位再调用 `sub_452200(level, -1)`，先随机物品类型，再用 `PropMdl` 的 `[等级/品级, 类型]` 查询具体物品 ID。
7. 若查询失败，会最多重试 4 次；成功后创建地面物品。

金钱与物品不是互斥关系。金钱命中后不会跳过物品判定，所以一次击败可能只掉钱、只掉物品、两者都掉，或两者都不掉。金钱分支会消耗 `rand()`，因此会改变后续伪随机序列位置，但从概率规则上不是“金钱替代物品”。

掉落数量只影响物品流程循环次数。每一个数量单位都会重新抽品质档位，并重新随机类型和具体物品；不是先一次性决定一个品质后复制多件。

## 物品品质与类型顺序

普通随机物品的顺序是先品质，再类型：

```text
RandProp 的 1..9 权重 -> 品质/掉落档位 level
sub_452200(level, -1) -> 按难度随机 Type 10/20/30
PropMdl 查询 [level, type] -> 具体物品 ID
```

因此，如果 `RandProp` 中品质 3 的权重命中，游戏会先得到 `level = 3`。随后 `sub_452200(3, -1)` 根据难度随机出 Type 10、20 或 30，再查 `PropMdl` 中 `等级/品级 = 3` 且 `类型 = 随机类型` 的记录。

1.05 中还有一个宝石档位修正：如果随机类型命中 Type 30，`sub_452200` 会按难度对输入 level 做偏移并夹在 `1..8` 范围内；Type 10 和 Type 20 使用输入 level。

| 1.05 难度内部值 | Type 30 查询 level |
| ---: | --- |
| 0 | `level - 1 - rand() % 4`，再夹到 `1..8` |
| 1 | `level - rand() % 3`，再夹到 `1..8` |
| 2 | `level` |
| 3+ | `level + rand() % 3`，再夹到 `1..8` |

Type 35 不在普通随机类型分支中自然生成。只有调用方显式传入 Type 35 时，才可能按 Type 35 查询。

## 普通击败概率

普通击败时 `bonus = 0`。

金钱判定：

```text
money_roll = rand() % 100
money_threshold = RandProp.掉钱机率

低难度时 money_threshold *= 2
其他难度时 money_threshold = money_threshold + money_threshold / 2

money_roll < money_threshold 时生成金钱
```

物品判定：

```text
item_roll = rand() % 100
item_roll < RandProp.掉宝机率 时进入物品掉落
```

物品品质判定：

```text
quality_roll = rand() % 90
从 RandProp 的 1..9 权重累计，quality_roll 落入哪个累计区间，就返回对应品质 1..9。
如果全部权重累计后仍未覆盖 quality_roll，则本次品质抽取失败，物品流程返回失败。
```

因为普通击败使用 `rand() % 90`，`quality_roll` 只会是 `0..89`。如果 `1..9` 权重总和超过 90，普通击败也不会自然落入 `90..99` 对应的尾部区间。

## 难度下的随机类型概率

当随机掉落逻辑已经决定掉落“物品”，并且物品类型由游戏随机决定时，药品、投掷物品、宝石的类型概率如下。

该表不包含：

- 是否掉落。
- 金钱掉落。
- 任务物品。
- 敌人背包已有物品吐出。
- 上游明确指定某个物品类型的特殊路径。

| 版本 | 玩家难度 | 内部编号 | 宝石 Type 30 | 投掷物品 Type 20 | 药品 Type 10 |
| --- | --- | ---: | ---: | ---: | ---: |
| 1.05 | 低 | 0 | 5% | 45% | 50% |
| 1.05 | 中 | 1 | 10% | 45% | 45% |
| 1.05 | 高 | 2 | 25% | 40% | 35% |
| 1.05 | 真正的战斗 | 3 | 40% | 30% | 30% |
| 1.05 | 英雄无悔 | 4 | 不存在 | 不存在 | 不存在 |
| 2.01 | 低 | 0 | 25% | 25% | 50% |
| 2.01 | 中 | 1 | 30% | 25% | 45% |
| 2.01 | 高 | 2 | 35% | 30% | 35% |
| 2.01 | 真正的战斗 | 3 | 40% | 30% | 30% |
| 2.01 | 英雄无悔 | 4 | 45% | 30% | 25% |

结论：

- 1.05 低、中难度明显更容易出投掷物品，宝石比例较低。
- 到“真正的战斗”时，1.05 与 2.01 的类型分布一致。
- 2.01 从低难度开始就更偏向宝石，并在“英雄无悔”继续提高宝石比例。
- Type 35 不在这段随机类型分支中自然生成。

## 1.05 随机掉落函数链

| 函数 | 说明 |
| --- | --- |
| `sub_452420` | 掉落判定、掉落数量、金钱/物品分支 |
| `sub_452390` | 按 9 个权重档位抽取等级/品级 |
| `sub_452200` | 根据等级/类型/难度从物品表选具体物品 ID |
| `sub_48B4F0` | 创建并投放地面物品 |

`sub_452200(a1, a2)` 中，只有 `a2 == -1` 或 `a2 == 0xFFFF` 时才会先随机决定物品类型。

1.05 类型分支：

- 类型 30 的生成点为 `0x00452271`，对应 `mov edi, 1Eh`。
- 若未命中类型 30 分支，后续 `0x004522E6` 会把类型设置为 10 或 20。
- 该函数本身没有把查询类型设置为 35 的逻辑。

`sub_452200` 有多个上游调用。若要修改敌人随机掉落的具体物品 ID，应只处理 `sub_452420` 内部调用返回点，避免影响其他路径。

1.05 中 `sub_452420` 内部调用 `sub_452200` 的返回地址：

- `0x00452630`
- `0x00452641`
- `0x00452652`
- `0x00452663`

## 2.01 随机掉落函数链

| 函数 | 说明 |
| --- | --- |
| `sub_45E5A0` | 随机掉落生成函数，内部按掉落配置计算金钱/物品，并调用具体选物函数 |
| `sub_45E390` | 根据等级/类型/难度从物品表选具体物品 ID，对应 1.05 的 `sub_452200` |
| `sub_49AB70` | 创建并投放地面物品，对应 1.05 的 `sub_48B4F0` |

`sub_45E390(a1, a2)` 中，只有 `a2 == -1` 或 `a2 == 0xFFFF` 时才会先随机决定物品类型。

2.01 类型分支：

- 类型 30 的生成点为 `0x0045E417`，对应 `mov esi, 1Eh`。
- 若未命中类型 30 分支，后续 `0x0045E447` 会把类型设置为 10 或 20。
- 该函数本身没有把查询类型设置为 35 的逻辑。
- 如果调用方显式传入类型 35，则可按类型 35 查询物品表。

2.01 中 `sub_45E5A0` 内部调用 `sub_45E390` 的返回地址：

- `0x0045E7B0`
- `0x0045E7C1`
- `0x0045E7D2`
- `0x0045E7E3`

2.01 中与敌人基础掉落概率相关的边界：

- `0x0043F6B1` 调用 `sub_45E5A0(..., 0.0)`，返回点 `0x0043F6B6`，对应普通击败/血量清空时的一次掉落。
- `0x0042CD6B` 调用 `sub_45E5A0(..., score)`，对应连招结束后的二次掉落路径。
- `0x0045E6F1` 调用内部 `rand`，返回点 `0x0045E6F6`，随后进行物品掉落 gate 判定。

## 连招二次掉落

如果清空敌人最后血量时处于连招攻击状态，最终连招得分超过 20 分，会触发二次掉落。1.05 中触发点在 `sub_423FB0`，调用 `sub_424180(this, 1, score)`，随后进入同一个 `sub_452420` 主流程。2.01 已确认也存在同类二次掉落调用，调用点 `0x0042CD6B` 会把 `score` 传入 `sub_45E5A0`。

`score` 在 `sub_452420` 中有两种用法：

```text
bonus_rate = score * 0.01
```

金钱判定会把随机 roll 缩小：

```text
(rand() % 100) * (1 - bonus_rate) < money_threshold
```

物品判定同时把随机 roll 缩小，并把阈值提高：

```text
(rand() % 100) * (1 - bonus_rate) < RandProp.掉宝机率 + score
```

金钱数量、物品数量也会乘上 bonus：

```text
final_amount = base_amount + base_amount * bonus_rate
```

品质档位抽取时，普通击败是 `rand() % 90`；连招 bonus 会把该值提高：

```text
quality_roll = rand() % 90
quality_roll = quality_roll + quality_roll * bonus_rate
if quality_roll > 99:
    quality_roll = 99
```

所以连招得分会同时提高掉钱概率、物品概率、掉落数量、金钱数量，并把品质 roll 往高档位推。`score = 20` 时，物品判定大致相当于 `(roll * 0.8) < 掉宝机率 + 20`；如果某敌人 `掉宝机率 = 30`，则命中条件约为 `roll < 62.5`，即从普通约 30% 提高到约 63%。

已知信息：

- 连招得分必须在击败敌人的时候仍处于连招中，才会触发。
- 得分由三部分组成，分布疑似为 `30 / 30 / 40`。
- 三个分量的具体含义未知。
- 1.05 得分计算函数：`sub_423580`。
- 2.01 得分计算函数：待确认。
- 1.05 掉落物品的函数：`sub_424180`。
- 2.01 二次掉落调用点：`0x0042CD6B`。
