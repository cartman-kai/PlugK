# 物品系统

## 物品类型

游戏中的物品类型目前整理如下：

| 类型 | 含义 |
| ---: | --- |
| 0 | 金钱 |
| 10 | 药品 |
| 20 | 可投掷物品 |
| 30 | 可镶嵌的宝石 |
| 35 | 疑似高难度下才会出现的宝石 |
| 40 | 任务道具 |
| 50 | 护身石，不需要镶嵌，可直接佩戴 |
| 60 | 特殊标记类道具分类 |
| 100 | 特殊宝石，部分特殊宝石可以把镶嵌宝石转换为护身石 |

## 物品池与容器

角色对象中多个容器槽位保存的是物品池索引，而不是直接保存物品对象。

- 容器空位为 `-1`。
- 非空值为物品池索引。
- 物品池索引指向物品对象。
- 物品对象中 `+0x18` 为物品 ID。
- 物品对象中 `+0x1C` 为数量。

已确认 1.05 与 2.01 的容器偏移一致，详见 [角色运行时内存](../runtime/player.md)。

## 物品模板名称

运行时 `PropMdl` 记录可反查物品显示名称。记录第 4 个 dword，即 `record + 0x0C`，指向一组文本指针；其中第一个指针 `ptrs[0]` 指向物品名，字符串编码为 GBK。

表头、记录结构和字段说明详见 [数据表与资源](../data_tables.md)。

## 地面物品名称显示

1.05 中 `sub_4127D0` 负责物品名称显示。该函数会通过物品模板生成 GBK 名称字符串，随后在 `0x004128AE` 调用 `sub_4CC4B0` 创建文字节点。

动态调试已用 GBK 字符串 `极品紫水晶` 精确断在 `sub_4CC4B0` 入口，确认返回地址为 `0x004128B3`，即来自 `sub_4127D0` 的调用点。将 `sub_4127D0` 调用前写入文字节点 `+0x0C` 的样式参数从 `0` 改为 `1` 后，地面物品名称文字背景消失，文字仍正常显示。

后续跟踪确认，`sub_4CC4B0` 只创建文字节点，节点字段 `+0x0C` 会在 `sub_4CC440` 中决定是否把背景参数传给 `sub_4B1DF0`：当 `+0x0C == 1` 时传入 `0`，地面物品名称无背景；当该字段为其它值时会传入 `1`，背景/边框会出现。`+0x10`、`+0x14` 未观察到会改变文字颜色。

文字颜色不由 `sub_4CC4B0` 的三个样式参数直接决定。地面浮动文字管理器由 `dword_55C1F8` 指向，构造函数为 `sub_4CC0C0`，其绘制路径为 `sub_4CC440 -> sub_4B1DF0 -> sub_4B25A0`。`sub_4B25A0` 先调用 `SetTextColor(hdc, this[24])`，即默认颜色来自文字管理器对象 `this + 0x60`。动态调试中将当前 `dword_55C1F8 + 0x60` 从白色改为 `0x0000FFFF` 后，地面物品名称变为黄色，且无背景效果保持不变。

`sub_4B25A0` 还支持字符串内嵌颜色控制码，会检测并移除 `$G`、`$Y`、`$B`、`$R`、`$W`、`$H` 等短标记，然后切换到 `0x00545C48` 附近的一组 `COLORREF` 颜色值。

plugK 的 1.05 “掉落物品显示颜色优化”实现没有长期修改 `dword_55C1F8 + 0x60`，因为该颜色会影响背包悬停物品、NPC 名字等同层文字。实现路径为：hook `sub_4127D0` 读取地面物品对象 `this+0x81` 的 `PropMdl` 记录，按记录字段 `type` 与 `quality` 判定是否需要染色；hook `sub_4CC4B0` 仅给本次创建的物品名字符串加内部标记；hook `sub_4B25A0` 在绘制该标记字符串时临时设置 `this+0x60`，调用原函数时传入去标记后的字符串，返回后立即恢复旧颜色。

`sub_4B25A0` / `sub_4C58F0` 是共享文字输出函数，不能由多个功能各自 `MH_CreateHook`。当前 plugK 由地面物品名称模块统一安装该 DrawText hook：掉落物品名称染色在标记字符串路径内处理，敌人血量显示通过同一 hook 的调用返回地址边界追加 HP 行；敌人血量模块只单独 hook 敌人名称绘制函数以取得当前敌人对象。

2.01 静态对照确认同构链路：`sub_41A500` 负责地面物品名称显示，读取 `this+0x81` 的 `PropMdl` 记录，经 `sub_4E4D90(record, 0)` 取名称后调用 `sub_4E1270` 创建文字节点；`sub_4E1200` 遍历节点并按 `node+0x0C` 控制背景；最终文字输出函数 `sub_4C58F0` 仍使用文字管理器对象 `this+0x60` 作为默认 `SetTextColor` 颜色，并支持同类内嵌颜色码。2.01 玩家可见效果仍需动态验证。

当前品质颜色映射：`1-2` 蓝色，`3-4` 绿色，`5-6` 橙色，`7` 金色，`8` 赤铜色，`9+` 紫色。1.05 对 `type=30/50` 生效；2.01 对 `type=30/35/50` 生效，其中 `type=35` 的自然生成路径仍需结合资源表和动态调试确认。

## 地面物品拾取

2.01 动态调试确认，地面物品拾取不应只手工调用入包函数 `sub_48DD30`。原始路径会先处理地面对象状态，再由包装函数把地面对象转换为入包参数。

主拾取链路为：

1. `sub_45E8B0` / `0x0045E8B0`：地面物品接触/触发拾取处理函数。
2. 函数内通过 `sub_4987D0(*(a2 + 0x18))` 取得角色对象，并检查 `*(a2 + 0x1A7)` 在 `10000..60000` 范围内。
3. 条件满足后调用地面物品虚表 `+0x20`。2.01 地面物品虚表为 `off_5519FC`，对应函数为 `sub_41A610` / `0x0041A610`，用于拾取前注销或标记地面对象状态。
4. 随后调用 `sub_48DCE0(char, groundItem)`。
5. `sub_48DCE0` 从地面对象读取物品模板、数量和附加字段，并调用 `sub_48DD30` 进入角色容器。

已观察到的地面物品对象字段：

| 偏移 | 含义 |
| ---: | --- |
| `+0x00` | 虚表指针，2.01 地面物品为 `0x005519FC` |
| `+0x67` | 对象类型，地面物品为 `23` |
| `+0x81` | `PropMdl` 记录指针，非对齐读取 |
| `+0x85` | 数量字段，`sub_48DCE0` 会传给入包函数 |
| `+0x89` | 字符串或附加文本指针；字符串非空时传给入包函数，否则传 `NULL` |
| `+0x8D` | 入包函数第 6 个参数来源 |
| `+0x91` | 入包函数第 7 个参数来源 |

普通物品拾取样本中，`sub_48DD30` 返回新建的背包物品对象；金钱拾取样本中，金钱也走同一条 `sub_45E8B0 -> sub_48DCE0 -> sub_48DD30` 链路，但 `sub_48DD30` 返回 `0`。普通物品成功拾取后，原地面对象随后进入 `sub_41A0D0(..., 1)` 析构并释放。

满背包拾取样本确认，`sub_48DD30` 内部会在失败返回前调用 `sub_49AB70`，按角色周围坐标重新创建同一物品的地面对象，然后返回 `0`。样本中原地面对象为 `0x170480C0`，物品 ID `0x2D`，数量 `1`；失败路径重新创建的新地面对象为 `0x1704A120`，坐标为 `(0x4A, 0x3B)`，`PropMdl` 记录仍为 `0x02A4E6D4`。原地面对象没有在入包失败点立即析构，而是在稍后的对象管理器清理路径 `0x004E4230 -> vfunc[0] -> sub_41A0D0(..., 1)` 中释放。

因此，自动拾取若要复用原始语义，优先考虑调用 `sub_45E8B0(groundItem, groundItem)` 或等价地复用其完整前置状态处理。直接调用 `sub_48DD30` 会绕过地面对象移除路径，存在复制物品或遗留地面对象的风险。

## 2.01 自动拾取

2.01 动态调试确认，原版 `Z` 键已经实现“拾取角色周围地面物品”。行为入口为 `sub_4247F0 / 0x004247F0`，`thiscall`，`a2 == 22` 时进入 Z 分支：

```text
sub_459D60(this+0x2C, this+0x30, 0xC0)
for each result:
    sub_45E8B0(groundItem, this)
    sub_459E10()
```

Z 分支调用 `sub_45E8B0` 的返回地址为 `0x00424E64`。自动拾取实现应只在自身自动触发上下文中用该返回地址过滤，不应影响玩家手动 Z 或鼠标/交互拾取。

2.01 当前场景动作槽表由全局 `dword_589E38 / 0x00589E38` 指向，每个槽位 6 字节。槽位 `+2` 是对象指针，索引用法为 `index & 0x7FFF`。当前 Z 行为对象可通过以下条件定位：

- `*(DWORD *)ptr == 0x00551E2C`。
- `*(DWORD *)(ptr + 4) == *0x00589E34`。

注意：早期草稿中写过 `scene + 0x9760`。动态现场显示 `0x00589E38` 当前值可等于该地址，但实现应读取全局 `0x00589E38`，不要固定从 scene 偏移推导。

已确认过滤样本：

| 样本 | `itemId` | `itemType` | 名称 | 结论 |
| --- | ---: | ---: | --- | --- |
| 金钱 | `0` | `0` | 金钱 | 可作为“仅金钱”模式 |
| 宝石 | `28` | `30` | 极品蓝晶 | 宝石模式包含 |
| 恢复品 | `4` | `10` | 小血瓶 | 恢复品模式包含 |
| 任务道具 | `133` | `40` | 上古玄铁 | 非“全部”模式排除 |

自动拾取模式当前定义：

1. 仅金钱：`type=0`。
2. 金钱+宝石：`type=0/30/35`。
3. 金钱+宝石+护身石+回复道具：`type=0/10/30/35/50`。
4. 全部自动拾取：不做物品类型过滤，等价定时触发原版 Z 行为。

自动拾取成功后的逐物品获得提示当前暂时关闭。代码中保留了从地面物品对象读取 GBK 名称、数量并输出 `[自动拾取] 获得：...` 的逻辑，但包在 `#if 0` 中不参与编译；自动拾取开关状态和拾取范围切换提示仍保留。关闭原因是大量拾取时文字输出和名称转码可能造成额外性能开销。

## 1.05 自动拾取

1.05 IDA 静态对照和动态调试确认，原版 `Z` 拾取路径与 2.01 同构。行为入口为 `sub_41C270 / 0x0041C270`，`thiscall`，`a2 == 22` 时进入 Z 分支：

```text
sub_44E460(this+0x2C, this+0x30, 0xC0)
for each result:
    sub_452730(groundItem, this)
    sub_44E510()
```

Z 分支调用 `sub_452730` 的返回地址为 `0x0041C892`。`sub_452730 / 0x00452730` 对应 2.01 `sub_45E8B0`，其内部先调用地面物品虚表 `+0x20`，再调用 `sub_47EEF0(char, groundItem)`，最终进入 1.05 入包函数 `sub_47EF40`。

静态候选：

| 项目 | 1.05 | 2.01 对应 |
| --- | --- | --- |
| 行为入口 | `sub_41C270` / `0x0041C270` | `sub_4247F0` / `0x004247F0` |
| Z 拾取扫描 | `sub_44E460(..., 0xC0)` | `sub_459D60(..., 0xC0)` |
| Z 扫描下一项 | `sub_44E510` | `sub_459E10` |
| 地面物品拾取入口 | `sub_452730` / `0x00452730` | `sub_45E8B0` / `0x0045E8B0` |
| Z 调用返回地址 | `0x0041C892` | `0x00424E64` |
| 地面/地图管理器指针 | `0x00558E4C` | `0x00589E34` |
| 6 字节对象槽表指针 | `0x00558E50` | `0x00589E38` |
| Z 行为对象 vtable | `0x00528CD4` | `0x00551E2C` |
| 地面物品 vtable | `0x005288F8` | `0x005519FC` |

1.05 当前场景动作槽表由全局 `dword_558E50 / 0x00558E50` 指向，每个槽位 6 字节。当前 Z 行为对象可通过以下条件定位：

- `*(DWORD *)ptr == 0x00528CD4`。
- `*(DWORD *)(ptr + 4) == *0x00558E4C`。

动态样本中，真实按 `Z` 命中 `0x0041C872` 时 `ESI=0x0EE7F1D8`，`*(DWORD *)ESI=0x00528CD4`，`*(DWORD *)(ESI+4)=*0x00558E4C=0x0E6455C0`。`*0x00558E50=0x0E64D4C8`，槽位 index `0x2542` 的 `slot+2` 可反查到该 Z 行为对象。身边没有物品时，`sub_44E460(..., 0xC0)` 返回 `0`，不进入 `sub_452730`。

1.05 实际地面物品 vtable 为 `0x005288F8`，`vtable+0x20` 指向 `0x004128E0`。静态创建路径中出现的 `0x0052988C` 是中间态或基类 vtable，不应作为自动拾取过滤条件。

| --- | ---: | ---: | ---: | ---: | --- | --- |
| 金钱 | `0x1588EB10` | `0` | `0` | `400` | 金钱 | 可作为“仅金钱”模式 |

## 随机类型生成边界

随机掉落选物函数只有在类型参数为 `-1` 或 `0xFFFF` 时，才会先随机决定物品类型。

如果调用方显式传入某个物品类型，则应按指定类型查询物品表，不应归入“随机类型倾向”逻辑。

## 物品进入槽位与叠加

1.05 `sub_47EF40` 与 2.01 `sub_48DD30` 在物品进入角色容器时会先按 `PropMdl.type` 决定特殊槽位。原版逻辑中，`type=20-29` 会优先处理投掷物堆叠，找不到可合并目标后进入投掷快捷槽 `56-61`。`type=10-19` 只有在角色对象字段 `this+0x314 == 0` 时才会进入快捷道具槽 `50-55`；该条件用于排除部分特殊恢复类道具。若不满足条件，后续会回退到普通背包 `0-49`。

plugK 物品叠加补丁会扩大进入可堆叠逻辑的类型范围，并在“找不到可合并堆叠后新建物品槽位”的选择处接管原版分派：1.05 为 `0x0047F077` 附近，2.01 为 `0x0048DE8A` 附近。分派逻辑必须保留原版 `this+0x314 == 0` 条件，否则特殊恢复类道具会误进入快捷道具槽。

## 叠加物品拆分

1.05 `sub_47EF40` 是角色容器入包函数。它会读取 `PropMdl` 模板、尝试寻找可合并堆叠、选择槽位、分配并初始化 `0x3C` 字节的物品对象、设置数量、注册到物品池管理器并把物品池索引写入容器槽位。若普通容器找不到可用槽位，会通过 `sub_480560` 取得角色/场景位置，随后调用 `sub_48B4F0` 创建地面物品。

plugK 的“拆分第一个叠加物品”功能复用这条游戏原生创建路径：`Ctrl+X` 会扫描当前背包页第一个可叠加且数量大于 1 的物品，每次拆出 1 个。若背包有空格，则调用入包函数创建拆出部分；若背包没有空格，则直接复用地面创建路径把拆出部分掉落到角色脚下。为了避免拆出的同 ID 物品被本次入包流程重新合并回原堆，拆分期间会临时 hook/拦截可合并堆叠查找函数，只在拆分标记生效时返回 `-1`。提示文案会从物品对象 `+0x14` 的 `PropMdl` 记录读取 `record+0x0C` 指向的 GBK 名称指针数组，取 `ptrs[0]` 转 UTF-8 后传给 plugK 提示接口。

| --- | --- | --- | --- | --- | --- | --- |
| 1.05 | `sub_47EF40` / `0x0047EF40` | `sub_47EDF0` / `0x0047EDF0` | `sub_480560` / `0x00480560` | `sub_40B0E0` / `0x0040B0E0` | `sub_48B4F0` / `0x0048B4F0` | `0x00558E4C` |
| 2.01 | `sub_48DD30` / `0x0048DD30` | `sub_48DBE0` / `0x0048DBE0` | `sub_48F360` / `0x0048F360` | `sub_4125B0` / `0x004125B0` | `sub_49AB70` / `0x0049AB70` | `0x00589E34` |
