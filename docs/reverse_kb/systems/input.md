# 输入与快捷键系统

## 2.01 数字键 1-4 获取路径

来源：IDA 2.01 静态分析。

游戏不是只通过窗口过程消费数字键消息。主循环消息处理后，`sub_40CEC0` 每帧先调用 `sub_4E3280(&byte_578F78)` 刷新键盘状态。`sub_4E3280` 会先把上一帧 `this+8..this+0x107` 的 256 个 VK 状态复制成按下历史标记 `this+0x108..this+0x207`，随后调用 Win32 `GetKeyboardState(this + 8)`。

因此 `byte_578F78 + 8 + VK` 是当前帧 VK 状态，`byte_578F78 + 0x108 + VK` 是上一帧/已按下标记。游戏判断按下时通常测试当前状态的高半字节：

- `VK_1..VK_4` = `0x31..0x34` -> `byte_578FB1..byte_578FB4`。
- `VK_NUMPAD1..VK_NUMPAD4` = `0x61..0x64` -> `byte_578FE1..byte_578FE4`。

`sub_4D8890` 会把这些状态映射到快捷栏槽位：

| 输入 | 状态字节 | 内部槽位 |
| --- | --- | --- |
| `1` 或小键盘 `1` | `byte_578FB1` / `byte_578FE1` | `sub_4D8260(0)` |
| `2` 或小键盘 `2` | `byte_578FB2` / `byte_578FE2` | `sub_4D8260(1)` |
| `3` 或小键盘 `3` | `byte_578FB3` / `byte_578FE3` | `sub_4D8260(2)` |
| `4` 或小键盘 `4` | `byte_578FB4` / `byte_578FE4` | `sub_4D8260(3)` |

`sub_4D8260(slot)` 读取界面/快捷栏对象中对应槽位的物品或技能引用。`slot < 6` 时会通过 `sub_48E130` 查询对象，再调用 `sub_48D890` 执行该槽位物品动作；这对应药品/快捷栏消耗类行为。

## 1.05 数字键 1-4 获取路径

来源：IDA 1.05 静态分析。

1.05 中键盘状态刷新函数为 `sub_4CE3D0`。该函数与 2.01 的 `sub_4E3280` 结构一致：先遍历 256 个 VK，把 `this+8+VK` 当前状态转换为 `this+0x108+VK` 上一帧/已按下标记，然后调用 `GetKeyboardState(this + 8)`。

主运行路径 `sub_405FB0` 开始处调用 `sub_4CE3D0(&byte_5489C0)`；另一个调用点位于 `sub_4043E0` 的状态切换/等待路径，也使用同一个键盘状态对象。

因此 1.05 中 `byte_5489C0 + 8 + VK` 是当前帧 VK 状态，`byte_5489C0 + 0x108 + VK` 是上一帧/已按下标记：

- `VK_1..VK_4` = `0x31..0x34` -> `byte_5489F9..byte_5489FC`。
- `VK_NUMPAD1..VK_NUMPAD4` = `0x61..0x64` -> `byte_548A29..byte_548A2C`。

`sub_4C42B0` 会把数字键和小键盘数字键映射到快捷栏槽位：

| 输入 | 状态字节 | 内部槽位 |
| --- | --- | --- |
| `1` 或小键盘 `1` | `byte_5489F9` / `byte_548A29` | `sub_4C3CA0(0)` |
| `2` 或小键盘 `2` | `byte_5489FA` / `byte_548A2A` | `sub_4C3CA0(1)` |
| `3` 或小键盘 `3` | `byte_5489FB` / `byte_548A2B` | `sub_4C3CA0(2)` |
| `4` 或小键盘 `4` | `byte_5489FC` / `byte_548A2C` | `sub_4C3CA0(3)` |

## Hook 方案

Hook 影响判断：如果补丁只在窗口过程里吞掉 `WM_KEYDOWN` / `WM_SYSKEYDOWN`，可以阻止游戏 WndProc 分支收到该消息，但不一定阻止 `GetKeyboardState` 在下一帧看到 `VK_1..VK_4` 的按下状态。Alt+1..4 与药品槽位冲突时，应优先考虑同步屏蔽游戏键盘状态表、拦截 `GetKeyboardState` 返回数据，或在 `sub_4D8890` / `sub_4D8260` 边界按 Alt 状态过滤数字槽位。

当前 plugK 对 `Alt+1..4` 采用快捷栏槽位执行边界过滤，而不是每帧清理数字键状态。WndProc 仍负责识别 `Alt+1..4` 并调用 `ExecuteUltimateHotkeySlot(slot)`；原版快捷栏消费路径由槽位执行 hook 阻止：

- 1.05 hook `sub_4C3CA0(slot)` / `0x004C3CA0`。该函数为 `__thiscall`，`ECX` 是快捷栏/技能栏对象，栈参数为 `slot`，结尾 `retn 4`。键盘分发 `sub_4C42B0` 调用后的返回地址为 `0x004C45DA`；鼠标/UI 路径 `sub_4C3DA0` 调用后的返回地址为 `0x004C3DCC`。plugK 只在返回地址为 `0x004C45DA`、`Alt` 按下且 `slot=0..3` 时跳过原函数，避免误伤按住 Alt 鼠标点击快捷栏。
- 2.01 hook `sub_4D8260(slot)` / `0x004D8260`。该函数为 `__thiscall`，`slot < 6` 会查询快捷栏物品并执行动作。键盘分发 `sub_4D8890` 调用后的返回地址为 `0x004D8BBA`；鼠标/UI 路径 `sub_4D8360` 调用后的返回地址为 `0x004D838C`。plugK 只在返回地址为 `0x004D8BBA`、`Alt` 按下且 `slot=0..3` 时跳过原函数。

Ctrl 组合键和自动拾取相关冲突仍通过键盘状态刷新 hook 处理：1.05 为 `sub_4CE3D0`，2.01 为 `sub_4E3280`。原函数刷新状态后，plugK 只清理实际配置使用的 Ctrl 主键和自动拾取 Z，不清理 `Alt` / `Ctrl` / `Shift` 等修饰键。每帧判断复用游戏已经刷新的 `keyboard_state`，不额外调用 `GetAsyncKeyState` / `GetKeyState` 轮询 Ctrl、Shift、Alt 或 Z。

屏蔽使用“直到冲突键释放”的 latch：如果玩家先松开 Ctrl/Alt、冲突键仍处于物理按下状态，hook 会继续清理该冲突键，直到 `GetKeyboardState` 中该 VK 不再按下，避免原版逻辑在组合键末尾补触发一次；修饰键本身始终还给游戏。latch 只遍历当前已屏蔽的 VK 列表，不扫描全部 256 个 VK。

1.05 / 2.01 已实现的屏蔽规则：

- `Alt+1..4`：在快捷栏槽位执行边界阻止 `slot=0..3` 的原版动作，避免触发原版快捷栏/药品槽位。
- `Ctrl+配置主键`：对背包/储物箱整理切换、宝石叠加切换、洗技能、拆分叠加物品等 plugK 快捷键，按当前 `g_pk_config.key_*` 配置清理对应主键。

单键长按类功能例如 `HoldShowItemName` 当前不默认屏蔽游戏输入；这类按键应按功能目标单独决定是否屏蔽，避免玩家把单键配置成原版拾取/交互键后失去原版行为。
