# 技能与招式系统

本页记录技能、招式、必杀技手势准备和释放链路中可复用的逆向结论。

## 基础概念

游戏中需要区分两套 ID：

| 名称 | 含义 | 常见来源 |
| --- | --- | --- |
| 技能 ID | 角色是否学会某个技能的判定依据 | 角色技能链、`player/skill.txt` |
| 招式 ID / Method ID | 实际释放动作使用的 ID | `player/skill.txt`、释放入口参数 |

释放函数使用招式 ID。判断角色是否拥有某个技能或必杀技时，应遍历角色对象的技能链，读取技能 ID。

## 角色技能链

角色技能链位于角色对象 `player + 0x364`。节点字段见 [角色运行时内存](../runtime/player.md)。

该链表已用于：

- 一键洗技能。
- 必杀技快捷释放前的已学习判定。

## 必杀技准备与释放链路

原游戏必杀技流程：

```text
按住 Alt 并用鼠标左键画手势
-> 手势识别得到招式 ID
-> 写入技能/快捷栏管理对象的准备释放字段
-> 下一次右键优先读取准备释放字段
-> 调用原始招式释放入口
```

手势不会改变当前右手技能。它只写入“准备释放招式 ID”，右键释放时该字段优先级高于当前右手招式。

## 技能/快捷栏管理对象字段

1.05 动态调试确认，2.01 静态分析确认字段布局同构：

| 偏移 | 含义 |
| ---: | --- |
| `+0x120` | 准备队列游标/索引相关字段 |
| `+0x128` | 当前左手招式 ID |
| `+0x12C` | 当前右手招式 ID |
| `+0xBEC` | 另一类临时选择/装备槽相关索引 |
| `+0xBF4` | 手势准备释放招式 ID |
| `+0xBF8` | 手势准备状态辅助字段，写入准备招式时清零 |

获取当前释放招式的优先级：

```text
if (*(manager + 0xBF4) != -1)
    return *(manager + 0xBF4);

之后才处理 +0xBEC、右手招式 +0x12C 和右手负值队列。
```

## 释放入口调用约定

1.05 与 2.01 的释放入口均为 `thiscall`：

```c
ReleaseMethod(controller, method_id, flag, target);
```

| 参数 | 含义 |
| --- | --- |
| `controller` / `ECX` | 战斗/输入 controller 对象 |
| `method_id` | 要释放的招式 ID |
| `flag` | 右键释放路径传入 `1` |
| `target` | 目标或上下文对象 |

动态调试确认：至少 1.05 释放入口在 `target == NULL` 时会使用 `controller + 0x3C` 作为上下文兜底。2.01 静态分析确认存在同构逻辑。

## Hook 边界建议

- 直接释放技能时应调用原始释放入口，而不是只写 `manager + 0xBF4`。写准备字段仍需要右键释放，不等价于直接释放。
- 若功能需要知道当前角色是否拥有必杀技，优先查角色技能链，不要依赖尚未确认的角色 ID 偏移。
- 怒气、动作状态、目标合法性等校验应尽量交给原始释放函数处理。
