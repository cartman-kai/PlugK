# 隐藏减伤常驻显示设计

本文定义玩家常驻 HUD 中“隐藏减伤”的数据语义和实现边界。1.05 已有静态地址与动态样本；2.01 已完成角色初始化、玩家战斗对象、来源集合和效果标志的静态迁移，但在用于正式功能前仍需一次短动态验证。

## 显示目标

默认紧凑显示建议为：

```text
保护减伤 66.7%  来源 3  效果44 关
```

其中“来源”必须理解为游戏本轮已经登记、尚未整体清空的不同攻击来源键数量，不是场上存活敌人数，也不是当前正在围攻玩家的 AI 数量。已登记敌人死亡后，其来源键仍可能保留；显示该值正是为了反映游戏下一次伤害实际会使用的除数。

2.01 检测到效果 113 时，建议改为：

```text
保护 来源 3  罡气护体（伤害钳1）
```

效果 113 不是固定百分比减伤，不能伪装成一个精确的百分数。

当玩家战斗对象尚未创建、切图期间不可读或版本不受支持时，应隐藏整行或显示 `--`，不得继续展示上一个对象的值。

## 已确认字段

| 项目 | 1.05 位置 | 2.01 位置 | 含义 |
| --- | --- | --- | --- |
| 已登记攻击来源数 | 玩家战斗对象 `+0x422` | `+0x42E` | 大于 1 时，伤害结算将阶段伤害除以该数量 |
| 效果 44 | `+0x1DB` 字节 | 相同 | 非零时主伤害再除以 2 |
| 效果 113 | 1.05 未见对应结算分支 | `+0x220` 字节 | 2.01 中效果 44 未启用时，将主伤害钳为 1 |
| 战斗阵营 | 玩家/来源对象 `+0x1A7` | 相同 | 双方相等时阶段伤害除以 2，但正常同组 AI 会停止攻击 |

## 比例定义

设当前已登记来源数为 `n`：

```text
围攻承伤倍率 =
    1.0              n <= 1
    1.0 / n          n > 1

效果承伤倍率 =
    0.5              效果 44 非零
    1.0              效果 44 为零

已确认保护承伤倍率 = 围攻承伤倍率 * 效果承伤倍率
保护减伤比例 = 1.0 - 已确认保护承伤倍率
```

示例：

| 来源数 | 效果 44 | 围攻减伤 | 已确认保护合计 |
| ---: | --- | ---: | ---: |
| 0 或 1 | 关 | 0% | 0% |
| 2 | 关 | 50% | 50% |
| 3 | 关 | 66.7% | 66.7% |
| 4 | 关 | 75% | 75% |
| 1 | 开 | 0% | 50% |
| 2 | 开 | 50% | 75% |
| 3 | 开 | 66.7% | 83.3% |

界面比例按浮点数保留一位小数。游戏内部使用整数除法并在来源除法后执行最低值修正，效果 44 又发生在更后的阶段，因此 HUD 只能称为“已确认保护减伤”或“保护减伤”，不能称为精确的“最终伤害减免”。随机伤害、攻击模板、暴击/附加效果、防御与绕过 `sub_4236B0` 的直接 HP 变化均不在该比例内。

2.01 的效果 113 应作为覆盖式状态单独显示，不参与上面的固定比例计算。静态代码是 `if (effect44) ... else if (effect113) ...`：二者同时存在时效果 44 优先，HUD 也应按实际分支显示效果 44 的减半，而不是显示“钳 1”。

## 战斗阵营的处理

`+0x1A7` 相等减半不应默认计入常驻比例：

- 它取决于具体攻击来源，不是玩家单方面持有的固定属性。
- 2026-07-30 动态测试中，玩家复制敌人分组后，敌人完全停止攻击，普通战斗无法继续取得同组受击样本。
- 它更适合作为同阵营伤害保护或友伤兜底；正常玩法中是否有稳定入口仍未确认。

如以后提供“调试详细模式”，可以显示玩家分组和最近攻击者分组，并在二者相等时单独标记“同组保护候选”，但不能把最近攻击者的结果外推到下一名攻击者。

## 更新和重置

- 数据可在已有输入帧或稳定渲染帧中只读刷新，不需要为显示功能再 Hook `sub_4236B0`。
- 1.05 `+0x422` / 2.01 `+0x42E` 在新来源首次伤害结算之后登记，因此 HUD 通常在该次伤害后才增加来源数；新的除数从下一次伤害开始生效。
- 状态 110“受伤旋飞”会清空来源集合；切图时玩家也观察到显示归零。
- 首版可每帧读取，或者以 `100..250 ms` 缓存刷新；少量标量读取不会产生大量日志或文件写入。

## Hook 与模块边界

1.05 通用文字输出 `sub_4B25A0` 当前由 `item.c` 统一拥有 Hook，并分发敌人血量追加绘制。常驻减伤显示不能再次对该地址调用 `MH_CreateHook`。如果复用该文字链，应扩展现有共享分发，并先确认一个每帧恰好一次且在游戏 HUD 表面上的调用返回地址边界。

建议新模块名为 `combat_mitigation_display.c/.h`，只负责：

- 取得当前玩家战斗对象。
- 读取来源数、效果 44，以及 2.01 的效果 113。
- 计算、格式化紧凑文本。
- 在共享文字绘制边界中追加一行。

调试面板的属性修改、攻击者列表和 CSV Hook 仍归 `combat_probe.c`，常驻显示不应依赖 `EnableCombatProbe=1`。

## 配置建议

首版建议提供独立开关，例如：

```ini
[Player]
ShowCombatMitigation=1
```

启动器文案建议为“显示隐藏受击保护”。默认是否开启、屏幕位置和是否允许热键切换，可在确定绘制锚点后决定。2.01 的 `off_551E2C` 玩家对象、`+0x42E` 来源数和 `+0x220` 效果 113 已由 Combat Probe 短测确认；常驻 HUD 仍需独立确认文字绘制锚点和共享 Hook 边界。

## 手工验证

1. 来源数为 `0/1/2/3/4` 时分别显示 `0/0/50/66.7/75%`。
2. 来源数为 `1` 时强制效果 44，合计显示 `50%`；来源数为 `2` 时显示 `75%`。
3. 进入状态 110 后来源数和围攻减伤立即归零。
4. 已登记敌人死亡后，在整体重置前显示仍保持原除数。
5. 切图、读档、退出场景和玩家对象临时不可用时不沿用旧值。
6. 关闭战斗调研工具后，常驻显示仍能独立工作。
7. 2.01 单独启用效果 113 时显示“伤害钳1”；效果 44 与 113 同时启用时按效果 44 分支显示，不宣称钳 1。
