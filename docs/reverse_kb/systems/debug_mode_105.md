# 1.05 调试模式

本文件只记录 `1.05` 版本程序中已经确认或初步确认的调试模式信息。`2.01` 版本尚未调研，不应直接套用本文中的虚拟地址。

## 入口与开启方式

来源：IDA 静态分析。

文本输入框提交后会进入 `sub_4C0670`。该函数会读取输入框内容，并检查首字符是否为反引号 `` ` ``。

开启调试模式的输入为：

```text
`tianxiawudi
```

注意事项：

- 反引号 `` ` `` 必须存在。
- 反引号会先被剥离，再比较后续文本。
- 比较使用大小写不敏感逻辑，因此 `tianxiawudi` 与 `Tianxiawudi` 等价。
- 首次匹配成功后设置全局调试开关 `dword_548644 = 1`。
- 调试开关打开后，后续以反引号开头的输入会作为调试命令交给 `sub_458410` 处理。

`sub_4C0670` 中的关键行为：

| 地址/函数 | 行为 |
| --- | --- |
| `sub_4B35D0(158)` | 获取文本输入框对象 |
| `sub_519192(96)` | 消耗或移除反引号字符 |
| `dword_548644` | 1.05 调试模式全局开关 |
| `aTianxiawudi` | 开启调试模式的口令字符串 |
| `sub_458410` | 调试命令/脚本动作解释器 |

## 命令解析规则

来源：IDA 静态分析，尚未动态验证全部命令。

`sub_458410` 是 1.05 版本的主要调试命令解释器。当前观察到的解析规则：

- 先按 `*` 分割一行中的多条命令。
- 每条命令再按空格分割参数。
- 命令名使用大小写不敏感比较。

因此调试输入大致形态为：

```text
`AddItem 参数1 参数2
`AddItem 参数1 参数2 * AddExp 参数1
```

参数数量和语义需要按每个命令分支继续确认。

#### `Shift+F2` 分辨率切换

来源：IDA 1.05 静态分析、2026-07-26 游戏内手工验证。原生运行环境下已确认可见分辨率切换效果；不同 Windows 兼容层和图形包装器下的行为仍待分别验证。

该快捷键位于 `sub_4748C0` 的 `dword_548644 != 0` 分支内，因此必须先输入带反引号的 `` `tianxiawudi`` 开启调试模式。按键条件为：

- `byte_5489D8` 当前帧高半字节非零，即 `VK_SHIFT (0x10)` 按下。
- `byte_548A39` 当前帧高半字节非零，即 `VK_F2 (0x71)` 按下。
- `byte_548B39 == 0`，即上一帧 F2 未按下；每次切换必须松开 F2 后再按。

分支调用 `GetSystemMetrics(SM_CXSCREEN)` 读取当前屏幕宽度，并按精确相等比较写入显示控制对象的待切换模式字段 `dword_5483A0`：

| 当前屏幕宽度 | 写入模式 | 原版目标分辨率 | 写入地址 |
| ---: | ---: | --- | --- |
| `640` | `5` | `800 x 600` | `0x00474D08` |
| `800` | `6` | `1024 x 768` | `0x00474CEE` |
| `1024` | `4` | `640 x 480` | `0x00474D26` |

宽度不是 `640`、`800`、`1024` 时没有兜底分支，快捷键不会修改待切换模式。这会影响已经处于宽屏自定义分辨率、DPI 虚拟化返回逻辑宽度或图形包装器改写 `GetSystemMetrics` 结果的环境。

`dword_5483A0` 不是未使用的调试变量。它是全局显示控制对象 `0x00548398` 的 `+8` 字段；主循环 `sub_4043E0` 将其与 `+4` 的当前模式比较，不同时调用 `sub_404D30(display, pending_mode, 0)`。`sub_404D30` 随后按模式设置 DirectDraw 显示模式：模式 `4/5/6` 在原版中分别对应 `640 x 480`、`800 x 600`、`1024 x 768`。

因此该快捷键在游戏启动后直接修改待切换模式，不会重新读取 `set.ini`，可作为启动阶段读取 `set.ini` 失败时的临时绕过手段：若从 `640 x 480` 启动，连续两次 `Shift+F2`（两次之间松开 F2）会先进入 `800 x 600`，再进入模式 `6`。当前没有证据表明这条调试路径会把结果持久化回 `set.ini`。

plugK 启用自定义分辨率时，[`resolution.c`](../../../plugK/src/resolution.c) 会把 `sub_404D30` 中模式 `6` 的 `1024 x 768` 常量替换为 `PlugK.ini` 的 `Width/Height`。此时 `800` 宽度下按 `Shift+F2` 进入的是 plugK 自定义分辨率，而非固定的 `1024 x 768`；进入非 `1024` 的自定义宽度后，再按该快捷键通常不会继续循环。该路径只能绕过 `set.ini` 的启动模式选择，不能绕过 DirectDraw 拒绝目标显示模式、plugK 未加载或补丁地址不匹配等问题。
