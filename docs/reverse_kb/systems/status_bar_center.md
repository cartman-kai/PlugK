# 主状态栏布局与按钮隐藏

## 当前实现：1.05 / 2.01 保留左侧 660 像素

配置为 `[UI] HideStatusBarButtons=0`，启动器显示「隐藏状态栏按钮」，默认关闭。旧 `CenterStatusBar` 配置不再读取，旧居中 Hook、点击兜底和日志实现已经替换。保留历史调研章节供追溯，不代表当前行为。

1.05 和 2.01 使用各自地址表安装同一套 Hook。运行时屏幕宽度至少 800 时，主状态栏绘制保留 `[0,660)`，640 模式保持原版。自定义宽度至少 800 且非 800/1024 时，分别修改 `0x004B365A / 0x004C69DA` 以加载宽模板。父对象不再居中，左右技能槽与 12 个快捷槽保持原坐标。

为降低硬裁剪的割裂感，主状态栏原绘制返回后会在裁剪边界内增加 6 像素 RGB565 渐隐。每行使用当前 `edgeRight` 右侧未写入的背景像素作为混合目标，只修改 `[edgeRight-6, edgeRight)`，`edgeRight` 及右侧像素继续完全不写入，因此不会重新遮挡其它窗口的按钮。目标表面宽度、像素格式或锁定条件不符合已确认的 16 位表面布局时，渐隐会跳过并保留原硬裁剪。

Hook 统一归属 `plugK/src/ui_offset_fix.c / Mod_StatusBar_HideButtons_Init`：

| 目标 | 调用边界与行为 |
| --- | --- |
| `0x004C31E0` | 主状态栏绘制期间设置线程局部裁剪作用域及目标 surface，返回后恢复 |
| `0x00501150`、`0x005033F0` | 仅对作用域内相同目标 surface 的精灵绘制合并原生裁剪；保留原源坐标、模式、透明参数 |
| `TextOutA`、`DrawTextA` | 仅在同线程状态栏绘制作用域内以 SaveDC/IntersectClipRect/RestoreDC 裁剪文字；DT_CALCRECT 不受影响 |
| `0x004C3690` | 执行状态栏悬停说明时暂时退出裁剪作用域，保留道具/技能说明完整显示 |
| `0x004B4800` | 仅在界面命中查询期间把主状态栏宽度限制为 660，然后恢复；同时影响特殊 100×100 命中区与普通矩形 |
| `0x004B3380` | 仅对主状态栏且光标 X 至少 660 返回无子控件，并清空选中对象，避免隐藏按钮继续触发提示/点击 |

通用文字函数 `0x004B25A0` 仍由物品名称模块持有 Hook，本功能没有重复安装。键盘分发 `0x004C42B0`、目标窗口对象和其它 UI 的命中路径保持原逻辑。八个 Hook 初始化任一步失败均撤销本次已启用/创建项，并尝试恢复模板立即数。

开启选项后在 DLL 同目录写入 `PlugK_StatusBar.log`，每次初始化覆盖。记录版本、配置、Hook 地址及结果、模板补丁、前 8 帧及分辨率变化时的绘制计数/控件矩形，以及最多 20 次隐藏区域命中查询（连续相同坐标/结果不重复）。绘制前后分开记录并关闭文件，便于识别原绘制期间中断；不把日志当作自动崩溃转储。

验证：Release|x86 构建通过；独立 x86 检查程序验证了裁剪交集、空交集、非目标 surface 直通、说明作用域恢复、线程隔离、GDI 裁剪恢复、版本/配置门控及 Hook 初始化失败回滚。检查程序使用合成回调，不能代替真实地址 Hook 或游戏效果验证。按用户安排，游戏内验证由用户执行。

手工验证：分别在 800×600、自定义分辨率进入存档，确认右侧无残留图像或鼠标阻挡、左右技能槽和 12 个快捷槽可操作、键盘可开关背包/属性等窗口、提示完整、弹窗可正常点击；关闭选项并重启对照。若异常，提供本次运行的 `PlugK_StatusBar.log` 及截图。用户已反馈 1.05「验证生效」，未提供逐项验证清单；2.01 待用户实测。

### 2.01 地址复核

样本 MD5：`e8ab11ec558c9cff6e30426b8003b0ea`。IDA 与 pyghidra 的样本哈希一致，ImageBase 为 `0x00400000`。新增目标已搜索源码及知识库，未发现其它模块重复 Hook。归属仍为 `Mod_StatusBar_HideButtons_Init`。

| 用途 | 1.05 | 2.01 |
| --- | --- | --- |
| 主绘制 | `0x004C31E0` | `0x004D77A0` |
| 普通精灵裁剪绘制 | `0x00501150` | `0x00518AA0` |
| RLE 精灵裁剪绘制 | `0x005033F0` | `0x0051AD90` |
| 悬停说明 | `0x004C3690` | `0x004D7C50` |
| 界面命中 | `0x004B4800` | `0x004C7BD0` |
| 子控件命中 | `0x004B3380` | `0x004C6700` |
| 屏幕宽 / 高 | `0x005485C0 / 0x005485C4` | `0x00578B50 / 0x00578B54` |
| 主状态栏全局指针 | `0x0055BBB0` | `0x0058D164` |
| 按 ID 取控件 | `0x004B35D0` | `0x004C6950` |

2.01 精灵链为 `sub_50BAC0 -> sub_50B440 -> sub_50CD10 -> sub_5051E0`。资源构造分别设置虚表 `0x005540A8 / 0x00554104`；虚表 `+0x0C` 分别进入 `sub_506700 -> sub_518AA0` 和 `sub_51AD90`。两个底层绘制函数均使用目标 x/y/width/height 裁剪，thiscall、10 个栈参数，汇编结尾为 `retn 28h`。

主绘制与提示函数本次 IDA 反编译失败，未把失败视为地址无效。汇编确认主绘制 `0x004D77FD` 调用动画绘制、`0x004D785D` 遍历子控件、`0x004D7C27` 调用提示函数，两者均 `retn 4`。pyghidra 成功反编译 `FUN_004d7c50` 为 `void __thiscall(void *this, void *surface)`，确认 `sub_4C6700` 结果写入 `this+0xA8`。Ghidra 尚未将主绘制入口识别为函数，因此主绘制结论来自汇编。

`sub_4C7BD0` 保留右下角 100×100 的特殊命中规则，随后遍历其它界面；可复用临时缩短父宽度的逻辑。`sub_4D8890` 键盘分发直接切换背包、属性等窗口，不依赖菜单按钮可见性。本次没有修改这两个版本的键盘分发，也没有新增主点击分发 Hook。

### 当前切口：平缓单峰轮廓 rock-v2 + RGB565 渐隐

用户已反馈两版直切通过，随后反馈 rock-v1 功能正常，但 8 像素锯齿缺口不够自然。rock-v2 复用原八个 Hook，以状态栏顶部到屏幕底部的可见高度为尺度，用固定单峰弧线代替周期性缺口：顶部和底部向内收 3 像素，中央逐渐隆起至 660，横向变化范围为 657～660。完整保留右技能槽 `[606,649)`。轮廓不依赖帧数或随机数，鼠标计算显式使用当前屏幕高度，不依赖上次绘制的线程状态。状态栏 Y 以上保持 660 边界。

精灵裁剪先与原裁剪、实际绘制目标和屏幕范围求交。`x<657` 的完整部分只提交一次；相交的右侧窄边缘按互不重叠的水平条带提交。每次仍传原目标坐标、源坐标、混合模式和透明参数，避免重叠混合加深或源纹理错位。只有触及边缘的精灵增加提交次数。

GDI 使用同一轮廓生成区域，与原 DC 裁剪求交；区域在主绘制内按需创建并复用，返回后释放。悬停说明仍退出裁剪作用域。界面命中期间根据当前光标 Y 临时缩短主状态栏宽度；子控件命中同样使用该 Y 的边界，因此透明缺口不保留隐藏按钮命中。

此版保留原岩石轮廓，并在裁剪内增加 6 像素的 RGB565 背景混合；没有新增黑色遮挡、阴影贴图或资源。游戏原生精灵函数的 16 位路径主要是色键复制和查表混合，调用参数中的透明值没有提供可直接复用的逐像素羽化，因此渐隐放在状态栏目标表面完成。日志使用 `edge=rock-v2 arc max-inset=3 height=screen feather=6px rgb565` 标记。渐隐和新轮廓的两版游戏内外观仍需用户验证，不能将 rock-v1 功能验证视为此次外观验证。

独立 x86 检查覆盖像素区域不重叠、左侧完整、边缘固定采样、精灵/GDI 轮廓逐像素一致、分辨率平移稳定、源参数保留、命中宽度恢复、原有作用域及初始化回滚。额外手工关注 1024×768 背包装备按钮是否仍完整可见、渐隐处是否有闪烁或颜色发灰、右技能槽外框是否完整、缺口可否操作场景，以及帧率变化。

## 1.05 左侧裁剪可行性复核（2026-09-13）

用户拟取消居中，保留原版左对齐，仅显示状态栏局部 `x=0..599`，隐藏其余部分。本节为替代方案评估，不代表已经实现。来源：idalib 对 1.05 数据库的静态反编译，样本 MD5 为 `c3161c47fb28412c620b0be6cddfaa6c`；两版宽模板均通过 GB2312、Tab 解码核对。未启动游戏验证裁剪。

### 600 像素边界

`JMMDL800.txt` 中，ID `15` 左技能槽为 `x=156`、宽 `43`（数据行 15、物理行 16）；ID `16` 右技能槽为 `x=606`、宽 `43`（数据行 16、物理行 17）。严格裁至 600 会隐藏右技能槽，并非只移除六个菜单按钮。两版模板这些字段一致。

ID `38/39` 锚点分别为 `x=250/413`、宽 `24`（数据行 18/19、物理行 19/20）。1.05 `sub_4C4860` 各生成六个槽，每次 X 增加锚点宽度，所以两组逻辑范围为 `[250,394)`、`[413,557)`，均在 600 内。图标、文字、经验条资源的实际绘制边缘仍需动态验证，不能只凭锚点推定。

### 绘制与输入证据

- `sub_4C31E0` 是主状态栏绘制入口。`0x004C323D` 调用 `sub_4F4BE0` 绘制主体，`0x004C329D` 调用 `sub_4B32A0` 遍历子控件；后续另画快捷物品、槽位文字和技能，最后 `0x004C3667` 调用 `sub_4C3690` 处理悬停提示。父对象宽度不是统一绘制裁剪开关。
- 精灵路径为 `sub_4F4BE0 -> sub_4F4560 -> 精灵虚表 +0x0C`。已跟到 `sub_4EFDC0 -> sub_501150` 和 `sub_5033F0` 两种实现。两者末参数均可接收裁剪区域，按 `x/y/width/height` 与目标表面及目标绘制矩形求交，再锁定像素并绘制。该参数不是 Win32 `RECT` 的 right/bottom 格式。存在原生局部裁剪能力，但尚未证明所有文字路径均经过这两个函数。
- `sub_4C3690` 会调用通用 `sub_4B3380`，并更新状态栏当前选中对象。因此隐藏部分需同时处理悬停和选中状态，不能只在点击回调末尾阻止窗口打开。
- `sub_4B4790 -> sub_4B4800` 决定鼠标下的界面对象。`sub_4B4800` 在遍历普通界面之前，先把 `[状态栏宽度-100, 状态栏宽度) × [屏幕高度-100, 屏幕高度)` 直接返回为状态栏。此分支未加状态栏 X，随后普通路径还通过 `sub_4B1D30` 取得命中矩形。释放隐藏区域需要同时考虑该特殊分支与普通矩形，并保留其它弹窗的命中优先级。
- `sub_4C42B0` 键盘分发直接通过背包、属性、小地图、日志、仙术编辑等窗口指针调用显示切换；这些分支不查询菜单按钮 ID `9..14` 的可见性。可保留状态栏对象及键盘更新，只隐藏鼠标入口；不要销毁窗口或停用整个状态栏。

### 建议边界

在宽模板模式下保持 X 为 0，保留模板适配，取消居中平移和属性/道具点击兜底。以主状态栏绘制调用为作用域，对其精灵提交附加裁剪并与原裁剪求交；右侧控件的绘制、悬停和鼠标入口同步禁用。通用命中修正必须只针对主状态栏，不可因屏幕 X 超过 600 就过滤其它窗口或场景输入。状态栏提示窗口属于独立显示内容，需要明确其裁剪边界。

现有 `ui_offset_fix.c` 已占用 `sub_4C31E0/sub_4C2D60/sub_4C3E40` Hook，替代实现应复用或替换该归属。此次源码搜索未发现 `sub_501150/sub_5033F0/sub_4B4800` 的其它 Hook；实际新增前仍须复查并明确共享调用边界。

结论：1.05 具备实现基础。严格 600 会失去右技能槽；若希望保留左右技能槽，可以评估至少 649 像素的逻辑宽度或单独重排右技能槽，外框所需余量待画面验证。2.01 仅复核了模板，新增底层地址尚未对照。其余待验证事项见 `research_queue.md`。本次未修改功能代码、未构建、未完成裁剪后的游戏内手工验证。

## 适用范围

本文记录 1.05 与 2.01 底部主状态栏的模板选择、坐标传播、鼠标命中和 plugK Hook 边界。结论来自两版 IDA 静态分析、`JMMDL.txt`、`JMMDL800.txt` 数据表，以及 1.05 的 `1024 x 768` 动态日志。

## 模板选择

两版均在界面管理器收到分辨率消息时按宽度加载模板：

| 宽度 | 模板 |
| --- | --- |
| `640` | `JMMDL.txt` |
| `800`、`1024` | `JMMDL800.txt` |
| 其它宽度 | 不加载新模板，继续使用此前的模板数据 |

1.05 的选择函数是 `sub_4B35F0 / 0x004B35F0`，`1024` 比较指令位于 `0x004B3658`，立即数位于 `0x004B365A`。2.01 的同构函数是 `sub_4C6970 / 0x004C6970`，对应指令和立即数位于 `0x004C69D8`、`0x004C69DA`。

plugK 开启 `CenterStatusBar` 且使用非原生自定义宽度时，把上述 `1024` 比较立即数替换为配置宽度，使自定义分辨率复用 `JMMDL800.txt`。`640`、`800`、`1024` 保留原版选择分支。

## 模板布局

1.05 的 `JMMDL.txt` 使用 GB2312、Tab 分隔；主界面记录为逻辑数据行 3、物理行 4。`JMMDL800.txt` 同样使用 GB2312、Tab 分隔；主界面记录为逻辑数据行 2、物理行 3。

2.01 的 `JMMDL.txt` 需要从严格 GB2312 回退到 GB18030，主界面记录同样为逻辑数据行 3、物理行 4。`JMMDL800.txt` 使用 GB2312，主界面记录为逻辑数据行 2、物理行 3。

宽屏模板中最右侧按钮位于 `x=775`、宽 `19`，因此居中计算把主状态栏视为 800 像素宽；640 模板按 640 像素宽处理：

```text
layout_width = screen_width == 640 ? 640 : 800
center_x = max(0, (screen_width - layout_width) / 2)
```

## 坐标与点击链路

主状态栏是界面 ID `3`。两版初始化函数都会注册子控件 `4/5/6/43/7..17/38/39`。通用定位函数把父界面绝对坐标与模板偏移相加，并递归更新全部子控件：

| 版本 | 主状态栏对象 | 模板重载回调 | 通用定位函数 |
| --- | --- | --- | --- |
| 1.05 | `dword_55BBB0` | `sub_4C2D60` | `sub_4B2B90` |
| 2.01 | `dword_58D164` | `sub_4D7320` | `sub_4C5F00` |

通用按钮命中函数 1.05 `sub_4B3380`、2.01 `sub_4C6700` 直接读取子控件对象的 `+0x14/+0x18/+0x1C/+0x20`，分别作为 `x/y/width/height`。因此移动父界面并调用原版递归定位后，按钮绘制和命中矩形会一起移动。

12 个快捷道具槽由模板控件 `38/39` 提供两组锚点。1.05 `sub_4C4860`、2.01 `sub_4D8E40` 每帧从锚点绝对矩形生成槽位；1.05 `sub_4C3040`、2.01 `sub_4D7600` 使用生成后的矩形判定点击。状态栏父界面平移后，锚点、快捷槽绘制和快捷槽点击会同步更新。

## Hook 归属与边界

状态栏居中归属 `plugK/src/ui_offset_fix.c`：

- Hook 两版各自的主状态栏模板重载回调、主状态栏专用绘制函数（1.05 `sub_4C31E0`、2.01 `sub_4D77A0`），以及主状态栏专用点击分发（1.05 `sub_4C3E40`、2.01 `sub_4D8400`）。
- 只在消息 `0` 的原处理完成后重新定位主状态栏。
- 绘制入口只在父界面 X 被后续流程恢复时再次定位，不在坐标已经正确时重复遍历子控件。
- 点击入口先按属性按钮 ID `11`、道具按钮 ID `14` 的当前绝对矩形记录目标，再调用原分发。只有目标窗口可见状态未被原分发改变时，才调用该窗口原有的 `vtable + 0x1C` 显示/隐藏函数一次；其它按钮及快捷栏不进入兜底路径。
- 不对通用定位函数 `sub_4B2B90 / sub_4C5F00` 调用 `MH_CreateHook`；这些函数由大量其它界面共享。
- 不修改敌人数据界面 ID `2`、背包、技能、传送地图或其它弹窗的父坐标。
