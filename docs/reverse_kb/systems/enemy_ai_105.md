# 1.05 敌人 AI 与角色动作模板

本文整理 1.05 中敌人行为逻辑与 `mb` 模板的关系，供人工阅读、后续 AI 辅助逆向和 Hook 设计共同使用。结论来自 IDA 静态分析与数据表验证；尚未经过游戏内日志验证的可见行为会明确标为“待动态确认”。

## 结论摘要

敌人 AI 由“程序状态机”和“模板动作池”共同决定：

```text
Role.txt / RolePrivate.txt
        │ 角色类别、阵营、性格、速度、索敌和战斗属性
        ▼
Role.rmd
        │ 每个角色可使用的 Skill.gop 技能组
        ▼
Skill.gop
        │ 每个技能组包含的 Skill.ini 动作
        ▼
Skill.ini
        │ 动作类型、权重、资源条件和执行参数
        ▼
ComeOn.exe AI 状态机
          决定何时索敌、追击、脱战、选组并执行动作
```

模板主要控制“角色拥有哪些动作以及动作的选择数据”，程序主要控制“在什么状态和条件下选择动作”。仅修改一个表通常不能完整重写敌人的高层行为。

## 资源加载链

来源：IDA 静态分析。

启动入口 `sub_405300` 依次装入角色、动作和技能相关资源。当前确认的关键加载函数：

| 函数 | 作用 |
| --- | --- |
| `sub_405300` / `0x00405300` | 启动模板加载入口 |
| `sub_4D57F0` / `0x004D57F0` | 装入 `Role.txt`、`BeastieMdl.txt`、`PropMdl.txt` 等角色/模型模板，并处理角色动作映射 |
| `sub_4D7B40` / `0x004D7B40` | 装入 `Skill.gop`，建立按技能组 ID 查询的运行时记录 |
| `sub_4D0500` / `0x004D0500` | 通用表格加载器 |
| `sub_4D0210` / `0x004D0210` | 从当前记录读取一个整数字段；字段号从 0 开始 |
| `sub_4D00B0` / `0x004D00B0` | 从当前记录读取字符串字段 |
| `sub_4D0230` / `0x004D0230` | 读取复合字段或列表中的元素 |

`sub_4D0210` 等函数依赖当前选中的表和记录。同一个字段号在不同调用上下文中含义不同，不能仅凭立即数把它固定解释成某个 `Role.txt` 或 `RolePrivate.txt` 列。

## Role.txt：通用角色模板

来源：数据表验证、IDA 静态分析。

`Role.txt` 使用 GB2312、Tab 分隔并带表头，共 163 条数据记录、47 列。它不是“敌人专用表”，而是通用角色/场景对象模板，包含：

- 玩家角色；
- 普通敌人和 Boss；
- 皇帝等 NPC；
- 拾遗小妖；
- 桶、机关、镇魂碑、唤妖塔、树等特殊对象。

因此，角色是否采用敌人 AI 不能只看它是否出现在 `Role.txt`。运行时对象类别、虚函数表、阵营分组和角色性格会共同决定行为。

### 已确认参与运行时初始化的字段

| 自然列号 | 表头 | 已确认用途 |
| ---: | --- | --- |
| 2 | 角色ID | 角色模板查询键 |
| 29 | 平时速度 | 参与移动速度和动画相关缩放 |
| 32 | 性格1 | 选择普通、首领或特殊对象 AI 分支 |
| 35 | 组 | 通过 `sub_421F40` 写入战斗对象 `+0x1A7`，用于阵营和选敌 |

### 当前原始数据未使用的思想列

1.05 原始数据中以下列全部为空：

- 第 30 列“平时思想”；
- 第 31 列“攻击思想”；
- 第 33 列“性格3”；
- 第 34 列“性格4”。

这只能说明发布版模板没有为这些列提供数据，不能单独证明加载器或其他版本从未支持它们。当前不应把“攻击思想”视为 1.05 敌人攻击规则的主要入口。

### 性格1 的已知取值

| 模板值 | 典型对象 | 静态结论 |
| --- | --- | --- |
| `0` | 大多数普通角色 | 走通用角色/敌人逻辑 |
| `1` | 多数 Boss、首领和少量特殊 NPC | 进入首领型距离决策辅助逻辑 |
| `20` | 拾遗小妖 | 进入寻找对象、接近和拾取相关逻辑 |
| `21` | 镇魂碑、唤妖塔、黄杨树 | 受击时走与普通角色不同的类别 3 动作路径，并执行额外状态处理 |
| `30` | 桶 | 进入桶/触发对象特殊动作逻辑 |
| `31` | 机关、机关2 | 进入机关特殊动作逻辑 |

黄泉树、怨魂等四条记录的原始值是 `21*0`。解析规则现已确认：普通整数装载路径最终调用 `atoi`，所以 `sub_4D0210(31)` 读取该字段时得到第一个值 `21`；`sub_4D0230(31, 1)` 会按 `*` 拆分字符串并取得第二个值 `0`。

这意味着 `21*0` 同时具有两层含义：普通性格比较把它当作 `21`，显式读取复合元素的逻辑还能取得附加参数 `0`。`sub_420520` 的目标过滤路径确实会读取 `Role.txt` 第 32 自然列的第二个元素，因此不能在编辑模板时把 `21*0` 简化为 `21`。

## RolePrivate.txt：角色私有属性

来源：数据表验证、IDA 静态分析。

`RolePrivate.txt` 严格 GB2312 解码失败，需要以 GB18030 兼容解码。有效表头包括：

```text
角色名称、角色ID、等级、战斗速度、跑步速度、索敌范围、性格2、比例、颜色、
HP、AT、DF、抗击打、命中率、闪避率、属性与主角接近、经验值
```

`sub_4247E0` 已确认读取程序列索引 9、10、11、13，即自然列号 10、11、12、14 的 HP、AT、DF、命中率，并施加难度倍率。

战斗对象 `+0x18F` 保存其 `RolePrivate.txt` 运行时记录。`sub_4247E0` 的反汇编明确先把该指针放入 `ECX`，再调用记录读取函数，因此 HP/AT/DF 等字段的表上下文已经确认。

自然列 7“性格2”是普通敌人 AI 节奏的重要输入。`sub_419000` 从战斗对象 `+0x18F` 的 `RolePrivate.txt` 记录读取程序列索引 6，按难度换算后写入战斗对象 `+0x32D`：

| 难度内部值 | `+0x32D` 初始化值 |
| ---: | --- |
| 0 | `性格2 * 2 + 2` |
| 1 | `性格2` |
| 2 | `性格2 / 2` |
| 3 及其他高值 | `性格2 / 3` |

`sub_42C3C0` 在非战斗状态根据 `+0x32D` 选择不同的全局时间基数，周期性调用 `sub_42D330` 搜索目标。`sub_42E5C0` 在战斗状态中也用 `+0x32D` 调节重新朝向、切换动作类别和目标互动的随机频率。静态控制流表明更高难度会把该值压低，从而切换到更积极的思考节奏；各全局时间基数的运行时数值和最终帧间隔仍需动态标定。

`sub_42E960` 还会为 `Role.txt.性格1 == 30/31` 的桶和机关再次读取原始“性格2”，把它用作特殊动作周期倍率。其触发条件可整理为：

```text
性格2 == 0
或
角色更新计数 % (全局时间基数 * 性格2) == 0
```

因此“性格2”具有两种已确认用途：对普通战斗角色，它先经过难度换算形成通用 AI 节奏档；对桶和机关，它还直接作为特殊动作周期倍率，数值越大间隔越长，0 表示不施加该周期限制。

自然列 6“索敌范围”的主链已经确认：`sub_42D330` 请求默认目标搜索时调用 `sub_4204D0(this, 0, -1)`；`sub_4204D0` 发现范围参数为 `-1` 后，从战斗对象 `+0x18F` 的 `RolePrivate.txt` 记录读取程序列索引 5，并以 `模板值 << 6` 作为空间查询半径。查询结果再由 `sub_420520` 按对象状态、阵营和当前战斗条件过滤，命中后由 `sub_42D330` 安装为目标并进入相应战斗状态。

因此该字段的单位是引擎逻辑格/模板单位，空间查询前乘以 64；不能直接按屏幕像素解释。敌人主 AI 在受特定状态影响和周期性距离判断中也会再次读取该字段，用于派生 `range - 2`、`range / 3 + 1` 或 `3 * range` 等局部阈值。

分析其他 `sub_4D0210(index)` 调用时仍必须先证明当前记录来自 `RolePrivate.txt`，不能仅凭相同数字索引作映射。

## Role.rmd：角色到技能组的映射

来源：数据表验证、IDA 静态分析。

`Role.rmd` 是 GB2312、Tab 分隔、无表头的映射表，共 162 条记录。格式为：

```text
角色ID    技能组数量    Skill.gop组ID1    Skill.gop组ID2    ...
```

示例：逻辑数据行 4、物理行 4 为：

```text
5    4    3    5    8    9
```

角色 ID 5 对应食腐僵尸，四个组在 `Skill.gop` 中分别命名为：

- 组 3：僵尸无头_僵尸抓；
- 组 5：僵尸无头_僵尸吐；
- 组 8：僵尸无头_初始态起身；
- 组 9：僵尸无头_初始态出地。

因此，调整某个敌人“拥有哪些候选动作”时，`Role.rmd` 是比 `Role.txt.攻击思想` 更直接的配置入口。

## Skill.gop：技能组

来源：数据表验证、IDA 静态分析。

`Skill.gop` 严格 GB2312 解码失败，需要回退到 GB18030；文件为 Tab 分隔且没有表头。`sub_4D7B40` 建立的单条运行时记录大小为 58 字节。当前确认的自然列：

| 自然列号 | 运行时用途 |
| ---: | --- |
| 1 | 组记录的一个 16 位标识/类型值，精确语义待确认 |
| 2 | 技能组名称，运行时保存为定长字符串 |
| 4 | 技能组 ID，也是 `Role.rmd` 引用的查询键 |
| 7 | 组内动作数量 |
| 8 起 | `Skill.ini` 动作 ID 列表 |

运行时记录还保存模板行索引和若干暂未命名的整数/16 位字段。没有确认的字段应保留编号，不宜根据个别名称直接命名。

## Skill.ini：单个动作定义

来源：数据表验证、IDA 静态分析。

`Skill.ini` 需要以 GB18030 兼容解码，当前共有 923 条动作记录。`sub_4D6510` 为每条动作分配 156 字节的固定记录，再按模板中的可变数量附加 32 字节子记录。

`sub_4D62A0` 已确认先读取程序列索引 `0..36`，即自然列 1..37；随后自然列 38 保存子记录数量，自然列 39 起每八个整数构成一条子记录。当前已确认字段：

| 自然列号 | 运行时偏移 | 已确认用途 |
| ---: | ---: | --- |
| 2 | `+0x02` | 动作名称，最长 32 字节 |
| 4 | `+0x24` | 动作 ID；加载时注册，也是 `Skill.gop` 成员引用值 |
| 12 | `+0x37` | 原始距离/范围量；后处理除以 64、最小钳为 1，保存到 `+0x90` |
| 22 | `+0x58` | 随机选择调节值；值越大，当前候选覆盖已有候选的概率越低 |
| 23 | `+0x59` | 动作类别；`sub_41B940(requested_type)` 用它匹配调用者请求 |
| 38 | `+0x8A` | 32 字节子记录数量 |
| 39 起 | `+0x8C` 指针 | 每条子记录包含八个整数，精确业务字段待确认 |

`sub_4D6180` 还会生成三个派生字段：`+0x90` 是自然列 12 除以 64 后的值，`+0x94` 来自自然列 13 的右移缩放，`+0x98` 表示子记录中是否出现首字段为 4 的记录。敌人主 AI 已使用 `+0x90` 参与与目标距离的比较，因此自然列 12 可以确认是动作距离/范围相关参数，但尚不能确定它代表攻击半径、接近距离还是动画覆盖宽度。

动作选择代码还会使用：

- 动作类别；
- 随机选择调节值；
- 当前状态下是否可用；
- 距离或资源门槛；
- 交给动作命令的执行参数。

自然列 22 不是普通的“数值越大概率越高”权重。对第 `n` 个合格候选，代码使用近似 `rand() % max(1, n + floor(n * value / 2)) == 0` 决定是否覆盖当前选择，所以更适合暂称“随机抑制/调节值”。在完整映射前，应继续使用“运行时记录偏移”和“模板自然列号”双重标识字段，避免因为表格中存在复合字段而产生错位。

## 敌人 AI 主更新函数

来源：IDA 静态分析。

敌人类对通用角色行为入口做了覆盖，核心更新函数为：

```text
sub_42C3C0 / 0x0042C3C0
```

该函数每次更新大致执行：

1. 调用基础角色更新，并检查暂停、无效状态、活动状态和移动能力；
2. 处理脚本显式指定的目标；
3. 调用特殊导航/角色性格辅助逻辑；
4. 在战斗状态中寻找或维护敌对目标；
5. 根据距离、路径、丢失目标计时和角色类型决定追击、等待或脱战；
6. 从 `Role.rmd` 给出的技能组中选择动作；
7. 把选择结果转换成内部角色动作命令。

内部动作命令目前只确认了不同整数 opcode 对应不同类别的移动、技能组或取消操作。未完整追踪接收端前，不应给所有 opcode 强行赋予玩家可见动作名称。

另有一个派生敌人类使用 `sub_42FC00 / 0x0042FC00` 包装上述主循环。它在角色空闲、没有当前动作或目标且计时器到期时，从 `Role.txt` 自然列 9“战休1”的复合值中随机选取一项，更新角色动画/状态偏移，随后仍调用 `sub_42C3C0`。这更接近特殊待机动画调度，不是另一套独立战斗 AI。

## 技能选择链

### `sub_41B940`：选择候选技能组

`sub_41B940(this, requested_type)` 会：

1. 读取当前角色对应的 `Role.rmd` 记录；
2. 遍历其中列出的 `Skill.gop` 组 ID；
3. 过滤当前不可用的组或动作；
4. 当调用者指定动作类别时，从类别匹配的候选中随机选取；
5. 当 `requested_type == -1` 时，依据动作记录自然列 22 的随机调节值做候选覆盖，并应用部分距离/资源条件；
6. 保存选中的 `Skill.gop` 组 ID 和组内成员索引。

代码中对若干动作类别存在额外规则：类别 10、11、12 仅在 `sub_424AA0` 返回的资源百分比低于 20、35、50 时进入选择，达到门槛会跳过；类别 7 还有额外排除或距离条件。类别名称和资源种类尚未确认，因此目前只能把 10/11/12 描述为“低资源触发类别”。

### `sub_420CD0`：解析当前动作

`sub_420D10` 把选中的 `Skill.gop` 组 ID 写入战斗对象 `+0x345`，把组内成员索引写入 `+0x349`。`sub_420CD0` 根据这两个字段，依次经过 `Skill.gop` 和动作 ID 查询，最终取得具体 `Skill.ini` 动作记录。

这个分层解释了为什么只看到一个敌人执行某招，不能直接推断该招的选择概率：概率可能来自 `Skill.ini` 权重，也可能来自高层 AI 调用某一动作类别的频率。

## 特殊性格分支

来源：IDA 静态分析；玩家可见效果待动态确认。

| 函数 | 触发条件 | 已确认的控制流 |
| --- | --- | --- |
| `sub_42E7B0` / `0x0042E7B0` | `性格1 == 1` | 根据目标距离使用约 128、320、512 的分段，选择近距离动作、保持/调整位置或追近目标 |
| `sub_42EAE0` / `0x0042EAE0` | `性格1 == 20` | 搜索一定范围内的对象，保存对象句柄，移动到附近，并选择拾取/特殊动作组；也会处理与敌对目标的距离 |
| `sub_42E960` / `0x0042E960` | `性格1 == 30/31` | 桶和机关类对象的特殊动作选择；`RolePrivate.txt.性格2` 控制周期倍率 |
| `sub_42D510` / `0x0042D510` | 特定导航/区域状态 | 返回出生点或区域坐标并在接近后停止；不是 `性格1` 分支 |

`性格1 == 20/21` 还共同影响受击结算。`sub_4236B0` 在正常阵营伤害和普通扣血公式之前识别这两个值，改为选择动作类别 3 并下发特殊动作；`21` 随后比 `20` 多执行 `sub_423660(1)`、`sub_41AC40(..., 2)` 和 `sub_41B8B0(1)`。`sub_4241D0` 也会在特定更新类型为 5 时跳过普通 HP/资源调整。辅助函数的最终可见效果尚未全部命名，但可以确认 `21` 主要是一条受击/状态特殊路径，而不是 `sub_42C3C0` 中独立的追击状态机。

距离常量的单位沿用引擎内部坐标，不应在动态标定前直接写成屏幕像素或游戏米数。

## 群体编队与难度

来源：IDA 静态分析。

`sub_447E30 / 0x00447E30` 是群体对象的周期更新，而不是单个敌人的普通攻击选择函数。当前确认它会：

- 定期清理已经死亡或无效的成员；
- 以领队为中心计算环形站位；
- 使用约 192、256、448 的编队半径；
- 向成员下发移动命令；
- 在条件满足时从成员动作池中选取动作，并向其他成员下发协同技能组命令。

函数中的第一处难度概率使用 `rand() % 600`，阈值按难度 0/1/2/3+ 分别为 `2/6/10/20`。另一分支使用 15%、30%、100% 等概率，并为特殊难度值 100 保留 60% 分支。

静态上可以确认这些概率控制编队/协同动作的调度频率，但具体在画面上对应哪一种集体攻击、诱敌或重新站位仍需动态日志验证。

## 与 BeastieMdl.txt 的边界

`BeastieMdl.txt` 包含索敌范围、对人反应、程序标识、程序数据和“高度AI”等字段，记录主要表现为小动物或环境生物。它与 `Role.txt` 的战斗角色体系有交集，但不是普通敌人技能组配置的替代品。后续应单独追踪其程序标识的分发函数，避免把环境生物行为错误合并进 `sub_42C3C0`。

## 已确认与待确认边界

### 可以作为后续静态分析基础的结论

- `Role.txt` 是通用角色表，不是敌人专用表；
- `Role.rmd -> Skill.gop -> Skill.ini` 构成角色候选动作链；
- `sub_42C3C0` 是敌人高层行为更新核心；
- `sub_41B940` 选择候选技能组，`sub_420CD0` 解析具体动作；
- `性格1` 的 1、20、30、31 存在明确程序分支；
- `sub_447E30` 负责群体编队和协同动作调度。

### 仍需继续确认

- `Skill.ini` 尚未命名自然列与运行时偏移的完整对应；
- `RolePrivate.txt.性格2` 对应的各个全局时间基数运行时值，以及 `+0x32D` 每一档对应的实际思考间隔；
- `性格1 == 21` 受击后额外三个状态辅助函数的玩家可见效果，以及复合值第二元素在目标过滤中的精确语义；
- `sub_42C3C0` 内部动作 opcode 的接收端语义；
- 群体协同动作在游戏画面中的具体表现。
